# 运行模型调用账本与用量查询

此能力逐次记录工作流运行中的供应商生成调用，不把会被循环、返工或重试覆盖的最新步骤回执当成累计账单。仅适用于已有访问保护或受控部署，不新增公网接入凭据，也不替代真实供应商费用对账。

## 读取当前运行

`GET /api/runs/<runId>/usage` 无请求正文和查询参数。运行标识使用 UUID，大小写归一化；只读取当前演示工作区。跨站请求拒绝，不存在或其他工作区的运行返回 404。成功、失败响应均禁止缓存；数据库异常、坏聚合或超过安全整数返回安全 503，携带 `retryable: true` 和 `Retry-After: 2`，不虚造零用量。

共享结构统一在 `src/contracts/model-usage.ts`，类型由 Zod 推导。完整返回示例：

```json
{
  "ok": true,
  "summary": {
    "runId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
    "tracking": "tracked-v1",
    "assessedAt": "2026-10-09T12:00:00.000Z",
    "calls": { "total": 3, "pending": 1, "returned": 1, "failed": 1 },
    "usage": {
      "completeCalls": 1,
      "incompleteCalls": 2,
      "invalidUsageCalls": 0,
      "inputCalls": 1,
      "outputCalls": 1,
      "knownInputTokens": 12,
      "knownOutputTokens": 6,
      "knownCallTotalTokens": 18,
      "recordedUsageComplete": false
    }
  }
}
```

本接口没有逐条调用详情、正文、标签、原始供应商错误、密钥或执行引擎句柄，不修改任务、工具、审批或投递状态。单条参数化 SQL 在同一数据库快照统计原运行与同工作区的调用，不读取 `run_steps` 的业务结果。检查时刻是本次请求时间，不是历史时间窗口查询。

## 状态与统计口径

- `pending`：调用意图已经持久登记，结果尚未确认。可能尚未发送、正在执行，或发送/返回后进程终止、结果补记失败；不能推断实际供应商调用次数、完成状态或费用为零。
- `returned`：供应商响应已取得并记录。业务字段解析、质量检查、后续工具执行或整个任务仍可能失败，不等于业务成功。
- `failed`：供应商调用抛错并记录安全类别，未取得可信用量。供应商可能已处理请求或计费，不能按免费处理。
- `total` 是已登记意图数量，含未确认意图。每次内部重试、格式修正及循环调用单独登记；不称为准确供应商账单次数。
- 输入、输出总量仅采纳供应商报告的非负安全整数；缺失、负数、小数、溢出或非数值保持未知。缓存读取/写入、推理输出是细分项，不再次加到输入/输出总量；细分大于对应已知总量标记无效。
- `inputCalls`、`outputCalls` 是分别具有已知输入、输出报告的返回次数；对应 `knownInputTokens`、`knownOutputTokens` 只加各自已知部分，没有样本时为 null，供应商明确报告零时为 0。
- `completeCalls` 要求输入与输出及其和有效，且没有已报告无效字段；`knownCallTotalTokens` 仅汇总这些完整记录，两侧已知小计与它不一定相等。可选细分未报告不单独造成无效。`invalidUsageCalls` 是含无效字段的返回次数，`incompleteCalls = total - completeCalls`。
- 归档调用不从统计排除，不能通过隐藏记录降低已经发生的已知用量。累计数值超过 JavaScript 安全整数明确拒绝，不取整或截断。

## 跟踪覆盖

新版本工作流将任务从 queued 初始化为 running 时标记跟踪版本 v1；已开始的历史运行重入、审批或等待恢复不回填此标记。历史或其他版本显示 `legacy-or-partial`，不能依据零记录声称从未调用模型。

`recordedUsageComplete` 只说明本次快照中、v1 跟踪范围内已登记的记录均有完整用量。运行仍在执行时后续还会新增记录；它不说明任务已经结束，不证明供应商金额，不涵盖登记失败后的不确定事务，也不是全站或整条业务链费用完整性承诺。

一个没有模型调用的 v1 运行可以为零条完整记录，但所有无样本用量小计仍是 null。模拟运行不发供应商请求，也不伪造供应商用量。

本批只覆盖工作流运行中的非流式 `doGenerate`。助手需求设计和模型连接测试不接入此账本；协作子运行、交接运行和验收运行分别有自己的记录，父运行不自动汇总后代。尚未接入的流式调用在供应商调用前明确拒绝，不能从中绕过登记。

## 持久性与失败边界

调用前事务锁定原运行，要求其仍为 running，从原运行派生工作区、创建人、助手和冻结版本，建立新的 pending 意图；不接受调用方覆盖归属。登记失败不发模型请求，可重试数据库失败使用安全 Workflow 错误。

取得响应或异常后只对原记录从 pending 写入终态；同一结果补记幂等，不刷新终态时间，不同结果、工作区或任务不能覆盖。已经发起的调用在任务取消后仍允许记录迟到响应，不重新启动任务，不声称取消撤销了供应商处理。

补记暂时失败最多重试同一记录两次，不能为补记再次调用模型。耗尽后保留持久未知状态并记录安全错误；原模型响应或失败继续原执行语义。不自动把未知记录改成零、不从最新步骤输出猜测补账，也不声称严格一次供应商副作用。

## 验证与部署

追加 `0031_runtime-model-call-ledger.sql`：新调用表、两个查询索引、运行覆盖列和仅用于原运行归属的外键。既有迁移不改写，历史运行不回填覆盖。健康检查同步要求新表、索引与关键列。生产须先人工应用完整迁移并验收受保护部署；本地不在共享或生产数据库执行写入测试。

单测覆盖安全数值、未知与零、细分不重复加算、覆盖口径、只读接口、登记失败、实际 AI SDK 内部重试、无效 JSON 响应、取消和补记失败不重调。隔离数据库覆盖并发登记/补记、冲突、租户、迟到响应、坏用量、溢出和历史覆盖；实际持久 Workflow 覆盖格式修正、业务失败仍保留用量、模拟运行及重复循环节点与最新步骤回执的差异。

真实供应商兼容与计费仍需人工验收；模型价格、货币费用、供应商账单对账、完整调用链汇总、并发配额、预算强制控制、监控页面与告警未在本批实现，不把本接口称为完整费用系统。
