# 最小业务闭环：MCP、模型与业务工具

本轮优先补真实执行断点，不继续扩展外围试算接口。后端链路为：指定 MCP 工具查询 → 映射所需字段 → 模型生成结构化方案（错误字段有限修正）→ 负责人查看方案并确认 → 业务工具登记 → 只交付选定字段。审批仍用已有持久 Hook，不增加轮询执行器。

## 服务端接入

使用既定 AI SDK 的官方 `@ai-sdk/mcp`，仅支持 Streamable HTTP；兼容 SDK 协商的旧式初始化与新式协议、JSON 和事件流响应。不提供 stdio、本地命令执行、自动 OAuth 登录或自动开放全部远端工具。生产建议 HTTPS，开发测试可以用本地 HTTP；地址和凭据只配置在服务端环境变量 `TOOL_REGISTRY_JSON`。

下面是可解析的只读登记示例。实际远端工具名称必须是 `lookup_customer`，其 inputSchema 必须与配置相同；从远端目录实际发现并核对，缺失、重复、变化或超出分页范围时不执行。远端说明与指令不会进入模型系统提示，远端注解不能改变本地授权、风险或重试规则。

```json
[
  {
    "id": "customer.lookup",
    "name": "查询客户",
    "description": "读取指定客户的业务信息",
    "protocol": "mcp-streamable-http",
    "operationKind": "read",
    "endpoint": "https://mcp.example.com/mcp",
    "headers": { "Authorization": "Bearer <server-configured-token>" },
    "action": "lookup_customer",
    "scope": "customer.read",
    "risk": "low",
    "inputSchema": {
      "type": "object",
      "required": ["customerId"],
      "properties": { "customerId": { "type": "string" } },
      "additionalProperties": false
    },
    "outputSchema": {
      "type": "object",
      "required": ["customerId", "amount", "active"],
      "properties": {
        "customerId": { "type": "string" },
        "amount": { "type": "number" },
        "active": { "type": "boolean" }
      },
      "additionalProperties": false
    }
  }
]
```

MCP 的 inputSchema 校验映射后的参数对象，并直接作为 tools/call 的 arguments；不会发送 action/input/outputs 信封或隐式附带全部上游结果。原 HTTP 工具保持该信封，不能用 MCP 规则替代。跨前后端协议与操作性质统一在 `src/contracts/tool-registry.ts`，`listToolRegistryOptions()` 只返回安全元数据；`ToolSpec` 必须冻结相同协议和操作性质，不能把写操作伪装成读操作。

后端执行模式只由冻结的 `protocol` 判断：`demo` 协议保留既有固定演示回执，不调用真实工具；合法的 MCP/HTTP 登记标识即使恰好为 `demo`，仍按真实协议查找登记、核对冻结配置和字段、执行 Harness 检查及既有业务防重路径。发布、启动与恢复守卫，以及顶层、子流程和并行的导入回绑使用相同边界。登记名称不再被当作演示模式，也没有新增保留名称或改写旧数据；缺失、变化或未绑定的真实配置不能退化为演示成功。

本次只修后端与共享校验，不改画布。基底画布的演示标签仍按登记标识判断，工具选择中的演示项还与同名真实登记共用选项值；内联选择也尚未完全使用登记协议。前端需独立对接协议边界与选项区分，不能以本次后端回归通过宣称画布已完成这项修复。

工具目录的展示名称和说明会隐藏已有规则可识别的凭据文字，并继续满足原长度契约；普通邮箱和业务说明保留。参数及结果定义可能包含默认值、示例和固定值，不能通过删除字段或改写 const/enum/default 来脱敏，否则会与真实工具规则漂移。定义中含已识别凭据文字，或凭据字段带非空文字固定值/示例时，整份登记配置明确无效；请把服务端凭据移到请求头等私有配置，而不是放进公开定义。只有字段类型声明不代表泄密，空值、零金额、否定值和正常用量保留，合法定义不被改写。检查仅处理普通被动 JSON，无法安全检查的循环、访问器、超过 32 层或 50000 项的定义关闭登记；不执行 toJSON，不声称能够识别任意形式的秘密。

目录、交付来源选择、上下文与结构化成果共用同一凭据字段判定。普通分词名称（如 `tokenizer`、`tokenizationMode`）和完整匹配的 `tokenUnit`、`tokenUsage`、`tokenCount`、`tokenLimit`、`tokenBudget` 等计量字段不再因包含 token 字样被误删或阻断冻结；原已支持的输入、输出、总用量也保留。独立 `token`、`accessToken` 及分词名称中附带的 `ApiKey`、`Secret`、`Credential` 等仍是凭据字段；普通业务字段的值或字段名中出现已有规则可识别的凭据文字也仍拦截，个人信息隐藏策略不放宽。不改字段名、值、成果容量、审批、操作性质或任何重试规则；纯链路及本机 SDK 假服务回归不代表真实数据库、Workflow 暂停恢复或供应商验收。

工具绑定、连接检查和实际 MCP 调用比较字段定义时，忽略对象键顺序而不依赖本机语言排序；不同 Unicode 写法仍是不同业务字段，不能归一化、合并或互换类型。远端及持久快照仅重排相同定义不要求重新发布，字段增删、类型或数组顺序变化仍阻止调用。本修复只调整这三处定义比较，不修改全局规范化函数、发布指纹、成果帧哈希、业务防重键或已保存的数据；HTTP 绑定保留原有 JSON 省略未定义可选值和正负零相同的规则。本机 SDK 假服务覆盖两种握手协议的检查→调用→成果选择链路及实质漂移前零业务调用，不代表数据库、真实供应商或 Workflow 验收。

回执优先使用 structuredContent，缺失时只兼容单段包含 JSON 对象的文本；不把普通文字、多个内容块、图像或资源自动猜成业务对象。isError、ok 非真、字段错误或超限都明确失败，不回显远端错误正文。参数最大 512KB，单请求响应最大 1MB，单连接总响应最大 4MB；整个连接/发现/调用限时 30 秒，目录最多五页、每页一百项。拒绝 HTTP 重定向，凭据不会跟随到另一个地址。

工具步骤保存结果时，被动普通 JSON 对象中由系统补充的自有、可枚举、布尔成功标记 `ok: true` 单独预留最多10字节；合法业务回执刚好达到1MB时，不能在业务操作已完成后因为这项内部标记被误判超限。HTTP 原始响应和持久业务账本仍限制1MB，不降低供应商可用容量、不扩大业务体预算、不删除成功标记或改写字段。其他节点、失败标记、继承/隐藏/访问器标记或自定义序列化钩子不获放宽；仅预留路径的被动数据检查按实际字节预算支持合法深层/多项HTTP JSON，已有字段定义检查的默认32层/五万项限制不变。运行步骤合计及完整上下文仍按包含内部标记的实际字节遵守原4MB预算。该边界由纯函数、步骤事务 mock 与真实HTTP解析加内存缓存回归验证，不等于真实数据库或Workflow验收。

连接检查和实际调用共用 32 次输送请求预算，包含 SDK 协商、GET 尝试、分页、心跳回复；实际调用还计入业务调用和会话关闭，检查关闭另有一次限时清理。真实 SDK 对本机假服务验证了五页目录每页一次心跳仍能调用工具，过量心跳则停止，不调用业务工具；连接检查只允许 SDK 的严格空心跳回复，不开放业务调用或额外输入交互。原时限、字节、分页和重试边界保持不变。

## 写操作和重试

operationKind 必须由管理员明确确认是 read 或 action，不信任远端 readOnlyHint/idempotentHint。action 必须同时登记 businessIdempotency=true 与 businessIdempotencyRetentionMs（5 分钟到 365 天），且真实服务器要保证相同 Idempotency-Key 的 tools/call 只产生一次副作用并复用回执；这不是 MCP 标准自动保证，不能只设置开关而未核对供应商行为。

SDK 内部工具重试关闭，暂时故障交给原 Workflow 有界重试。同一步的重试复用同一个键，循环的新步骤使用新键；键只发到 tools/call，不用于初始化、目录发现或关闭。需要跨运行业务防重时配置原 toolOperation，继续走同一持久账本、租约、回执复用和过期人工核对，不绕过既有审批或防重有效期。缺少保证的 MCP 写操作不会进入有效目录。

未显式配置跨运行键的 MCP 写步骤也使用同一持久账本，按本次运行和唯一稳定步骤定位复用回执、保留原始防重截止时间；无法确认旧步骤是否已写入时先阻断并留待核对，不当作首次调用。显式业务键仍负责跨运行防重，不被默认步骤定位替代。

顶层步骤标识仍限制为原有英文数字格式，子流程和并行内部步骤可保留合法中文标识。工具步骤的外部防重键只对不能作为 HTTP 请求头发送的字符做版本化摘要：先序列化运行、节点、步骤三段标识，再取 SHA256，得到短 ASCII 键；同一次重试保持相同键，循环新步骤另取新键。原先可发送的键（含合法 Latin-1 与内部制表符）不裁剪、不规范化，显式业务操作键完全不变。已有账本的请求摘要若不匹配仍拒绝重发，不迁移或覆盖历史记录。这不提供额外远端防重保证，供应商仍须真实兑现登记承诺。

## Harness 运行边界

`HARNESS_POLICY_JSON` 复用已有 Harness 分支的严格规则契约，空值允许原行为；无效 JSON、未知条件、重复编号或版本错误关闭模型和工具调用。匹配条件全部满足才生效，匹配拒绝优先于允许；默认无匹配时允许，因此它不是默认拒绝式权限系统。可按模型/工具、节点、登记工具、范围与风险拒绝。例：

```json
{
  "version": 1,
  "rules": [
    {
      "id": "hold-writes",
      "effect": "deny",
      "when": { "nodeType": "tool", "scope": "customer.write" },
      "reason": "业务登记尚未完成联合验收"
    }
  ]
}
```

策略在主流程、内联工具与模型执行前检查，也覆盖调用模型的业务判断节点。轨迹只记录安全的允许/拒绝结论，不保存管理员原因正文或编号，避免配置误含凭据。模型上下文检查使用实际映射后的输入和上游，不因为未选的原任务很大而误拦；超过现有输入/上游/反馈分段容量时直接停止，不以提示截断掩盖业务数据缺失。`HARNESS_MAX_PROMPT_CHARS` 在 1000–128000 范围内，计算实际完整系统和用户提示（含字段规则），结果格式修正的追加反馈再次检查。该检查不宣称覆盖供应商另行添加的内部 token 或证明业务语义正确。

已有结构化结果修正、质量返工、资源准入、模型调用账本和审批保持各自职责；Harness 不是一个另起的自主代理执行框架，也不能保证抵御所有提示词攻击。

## 可复现样例和验收边界

重复发布比较完整的持久清单及发布级别。新清单先转为与 JSONB 保存一致的 JSON 表示，再与最新版本比较；可选元数据中的 undefined 对象字段被存储省略，不能因此误创建新版本。模型选择、知识范围、运行输入、交付来源、工具规则、审计或数组顺序发生实质变化仍不复用，明确 null 不等于省略字段；不能转成 JSON 的清单不复用。该修复不改变全局 JSON 比较、流程指纹、发布锁、设计审计、模型门禁、评测门禁或审批，也不修改版本和接口字段。
