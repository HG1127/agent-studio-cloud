旧 V5.7 的 WorkflowDraftCanvasV25、ProSchemaStudio 工作约定与字段编辑是产品参考；旧项目只读。当前 d59 的 InputMapping、ModelOutputConfig、WorkflowNode、WorkflowDraft、运行时来源与模型校验器以及只读 POST /api/workflows/input-preview 是真实接口依据，不增加数据库、后端消费者或共享结构。

## 实际行为

- 顶层、步骤组和并行工作均可展开“输入与结果约定”，真正接入 FlowCanvas 的当前完整草稿、撤销、重做和原 saveWorkflowAction。首次未展开不挂载重表单；收起再展开保留本地未应用编辑，不自动补配置。
- 逐层输入来源使用共享映射契约，点名不拆层；零、否、空值和明确回退保持类型。引用只定位实际定义，不保证当前运行路径已有成果。启用额外上游成果、删除、清除与应用均明确确认。
- 模型对象规则、请求模式和有限格式修正沿现有消费者；未知旧规则只读、原开发者模拟样例明确边界。规则不等于业务质量或提供商兼容，不自动生成业务结果。
- 组内运行标识完全由 prepareSubflow/prepareParallelBranches 准备。写回只更新所选 inputMapping 或 modelOutput，原始 id、缺省标识、next、重试、未知业务字段、分支与列表顺序保留；运行时限定标识不会成为新顶层节点。
- 子步骤单项合法仍须校验实际完整父草稿的共享容量、来源和模型约定。父草稿拒绝时编辑与原值均保留，子编辑器不显示虚假“已应用”。
- 输入定义、交付定义和其他整草稿变化均使输入编辑/确认失效；变化再恢复原值不会复活旧确认，须明确重新读取。只读试算仍由用户明确提供样例，无自动补值、写入或执行；样例不是实际运行证据。
- 尚未应用的编辑保存在当前检查器内存；切换到其他步骤或离开页面的完整未应用表单保护仍需后续补齐，不能把画布已应用草稿的离页保护算作该编辑器保护。
