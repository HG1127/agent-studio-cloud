# 启动资源拒绝回执前端增量（1423）

本包只修改两处真实启动器及专属展示和规格，不修改共享契约、Server Actions、查询、数据库、配置或旧 V5.7。作者基线为只读 `frontend-visible-integration-d43` 的实际 1423 文件；不是仅以 HEAD 代替未提交文件前像。

## 真实能力和显示范围

- 继续调用现有 `startRunAction`；仅使用现有 `StartRunResult.resourceLimit`。
- `RunResourceLimitNotice` 对收到的未知值执行共享 `ExecutionResourceLimit.safeParse`，不自建类别或数值结构。严格校验通过才显示执行链数量、模型调用次数、协作任务数量，以及这次回复中的已用数量与上限。协作上限为零是合法信息，不用真假值判断数值。
- 缺失、空值、未知类别、额外字段、负数、非整数、非法范围、未达到上限等不生成限额说明、默认数值或资源链接，原服务端错误仍显示。
- 说明明确是本次启动回复，不是当前全局实时余量、历史额度或费用；不能用限额拒绝证明先前未知请求未创建任务。
- `/harness#execution-resources` 仅提供用户手动查看入口，`prefetch={false}`。不主动读取资源状态、不修改资源设置、不自动重试。网页试运行未知时的离开确认保护继续适用于此链接。

## 请求与归属保护

- `RunLauncher` 的外层按助手、页面正式版本号和正式版本就绪状态划分实例，内层用 layout 生命周期代次隔离旧 success、failure、throw 和 finally。该实例键只是表单归属，不是服务端启动版本锁；页面明确说明实际启动使用提交时的当前正式版本。
- 同批重复提交由同步 ref 拦截。原输入、原完整 `RunStartInput` 和请求标识保留；未知请求的后续 `!ok` 或异常都不能解除原输入锁定。真正 `ok` 或用户明确确认开始新请求后才清理未知请求。
- 首次普通非 retryable 拒绝仍允许修改原填写。首次 retryable 回复沿用原请求核对。`WebToolTrialRun` 保留现有创建确认、离开保护、固定输入、实例代次和迟到回执隔离，补齐首次 retryable 回复的锁定。
- `RunLauncher` 在真正成功回复后先同步保存已创建标识，再保存回执状态并导航；无论导航仍未完成还是抛错，同一实例都禁止再次提交和修改输入，并始终保留关闭预取的真实任务详情链接。导航失败不是创建状态未知。只有新归属实例可重新开始；“确认开始新请求”只允许处理真正未知的请求，不能清除已确认创建记录。
- 新一次准备/提交、替换错误、成功、实例切换和显式新请求清理旧限额说明；不会把前一次回执冒充新一次结果。
