# 成果投递面板（源码候选，尚未验收）

基线为冻结1423文件的实际d43前端快照，不是仅d43提交。作者目录独立，冻结树和旧V5.7只读。

## 实现范围

- 运行详情新增独立“成果投递”导航及客户端面板，不改原结果、审批、协作、反馈或用量读取。
- GET现有 /api/runs/[runId]/delivery，仅通过共享 RunDeliveryResult 核对归属；展示六种真实状态、尝试次数、日期和人工补投次数。
- 空记录只表示没有已保存记录，不推断接收方是否配置。读取失败及不合法结果均未知，绝不提供猜测的写表单。
- 原始后台错误、目标／任务／回执／用户标识及请求摘要不进入业务界面；错误按已有真实服务端原因归类成简单中文。日期明确北京时间。
- 仅失败快照可填写核对原因，确认后通过原POST Route Handler调用现有唯一写Action。服务端继续核对成果、次数、期限和接收方配置；前端不保证补投获准。
- 请求、原因和确认字段一次固定；同步占用防止同批重复提交。抛错、5xx、非法或错归属回执均未知，只允许手动先重读原投递后再确认重发同一原请求。
- 原请求未知后，即使本次重发被403／409等明确拒绝，仍锁住原请求，不认为最初提交未保存。GET新失败也不会自动解锁未知请求。
- 登记正回执只确认补投请求存在，不推断等待发送或已送达。要开始新请求，必须先重读同一投递的新失败快照，并核对原请求的唯一人工记录；实际按钮事件再次检查当前读取状态。
- run标识通过共享契约统一小写后确定会话。layout代次和读取中止防止卸载、A到B到A、StrictMode及晚响应污染新页；中止浏览器读取不取消服务端发送。
- 未知／提交中保留离开提示及普通导航／卸载保护，不声称可拦截所有浏览器返回。原请求只保留本页，离开后须先核对已保存记录。

## 专属规格

组件规格使用真实叶子与真实RunDetail组装，只有queries/actions、模型用量读取及fetch等I/O边界mock；覆盖父页独立失败、六状态／空／加载、异常解析与归属、确认、防双发、未知后负回复、原请求重用、登记后新失败、实时旧按钮保护、大小写同实体、已送达幂等回执、StrictMode／ABA／晚响应和离开保护。

桌面Playwright规格不注入成功投递记录或成功回执；需要CI先在证明归属的隔离Neon准备真实失败记录与完整成果，配置CI专用、非生产、防重接收方。任务须未过期、人工历史少于20次，实际Action仍负责接收方及成果校验。

CI准备完成后提供非密钥任务标识 RUN_DELIVERY_E2E_RUN_ID，并明确设置 RUN_DELIVERY_E2E_ALLOW_RETRY=1 才能运行真实补投规格。缺少条件时规格明确失败，不skip、不借用生产数据或连接串。首次POST通过真实Route Handler保存后只丢弃浏览器响应，再真实GET核对人工历史、以原完整请求真实POST取得幂等回执，最后核对只新增一条历史。不声称已验证外部业务送达或完整Workflow集成。

规格确实会新增一条隔离人工补投记录并允许后台发送；CI须自行证明接收方与数据安全，管理专用测试数据生命周期。作者不创建数据库、不调用这些接口、不运行规格。
