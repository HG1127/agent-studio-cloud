# 网页工具与运行控制台的读取初始化边界

目标为 `codex/frontend-visible-integration-d43` 的实际 d43 后端与已冻结前端代码，不修改旧 V5.7 项目。

## 已有失败证据

现有隔离预览没有经归属核实的数据库配置。CI 专用对话在当前 1417 文件版本上实测：连接页返回 200；网页工具和运行控制台返回 500，桌面截图均为 Next.js 开发错误叠层，错误来源为 `src/lib/db.ts` 在模块初始化时缺少 `DATABASE_URL_POOLED`。

既有中文读取失败处理在查询调用的回调中，而静态查询模块导入先初始化数据库，因此失败发生在页面加载阶段，尚未进入安全读取回调。不能将这次预览结果称为完整页面或关键业务路径通过。

## 最小前端修改

- `WebToolSources`、`WebToolTrialResult` 和运行控制台页面，在各自现有 `withSafeQueryError` 回调中加载实际服务端查询模块，再调用同一真实查询。
- 查询参数、工作区范围、版本与任务归属核验、读取顺序、并行与独立失败状态保持不变；没有新增业务查询、替换查询结果或移除后端校验。
- 模块加载失败与 I/O 失败同样呈现“暂不可读取”的中文状态，不显示空版本、零任务、默认资源数、空历史或执行成功。
- 重新读取仅走原有页面刷新入口，不启动任务、提交决定、写资源设置或取消服务端执行。
- 不检查或复制环境变量，不修改数据库初始化、contracts、Server Actions、queries、Route Handlers、表结构、依赖或验收配置。

客户端的资源面板使用现有 Route Handlers；网页工具试运行的客户端模块通过 Next.js 的 Server Action 引用调用真实动作。回归规格仅在动作边界提供未调用的替身，不能据普通 Vitest 直接模块图推断 Next.js 服务端引用行为。
