# 页面错误恢复增量

冻结组合树当前使用 Next.js 16.3.8。已完整读取该安装包的 `error.md`：自 16.3.0 起，错误页的 `retry` 会重新获取并渲染内容；`reset` 只清除错误状态，不重新获取。当前安装包的错误边界实现也明确区分这两条路径。

本增量把仍使用旧回调的 15 个控制台、列表及详情错误页改为当前框架提供的 `retry`，保留原中文反馈、返回位置和用户手动点击行为。不添加自动恢复、业务重试、写操作、查询或环境配置。已经使用 `retry` 的全局、外部连接和业务操作错误页不改动；共享恢复组件不改动。

同步更新 3 份既有规格的框架参数，并新增直接渲染 15 个真实错误页的规格。不同的 `retry`／`reset` 函数同时传入，分别断言点击与键盘恢复只调用 `retry`，挂载与重新渲染不自动调用，不显示私有错误消息或摘要，原安全返回链接仍保留。这是作者规格，不代表已运行或已证明浏览器重读成功。

作者基线的 18 个修改文件均与冻结 1423 文件组合的精确字节相符；另外只新增本说明与专属规格。独立 scratch 中的严格补丁应用、回退及 SHA 对照只证明源码可机械应用，不代替任何功能验收。未安装依赖、审计、类型生成、类型检查、lint、Vitest、构建、迁移、数据库/Workflow 集成测试、Playwright、浏览器或 acceptance。所有功能检查未完成，发布资格为否，最终组合源码交 CI/CD 专用对话完整验收。
