# 顶层智能处理返工默认恢复

这是 Root27 r2 / 冻结526候选之后的独立源码增量，不覆盖已有候选，不是验收通过记录。只做桌面网页端；旧 V5.7 项目、共享契约、执行器、数据库与依赖均不修改。

## 实际能力与交互

现有 WorkflowNode.retry 保存总尝试次数与等待参数。实际 selectQualityRepair 在 retry 未设置时使用总尝试2次，即缺失必需结果时最多额外返工一次。界面据此增加独立的“恢复质量返工默认设置”确认，移除当前顶层智能处理步骤的整个已知 retry 对象，不把解析默认写回原稿。它不是禁止返工、网络重试、恢复旧版本或立刻执行；原次数1时，恢复默认反而允许一次额外返工，确认文案明确说明。

默认恢复仅在当前完整合法草稿、真实所属步骤、修订和画布暂存接收入口齐备时提供。未知额外 retry 字段阻止整个对象移除，原次数编辑仍保留它们；已省略 retry、其他类型、组内步骤、冻结版本和缺接收入口不造恢复按钮。这个操作是基于真实契约与消费者补齐可逆配置交互，不声称旧 V5.7 已有相同按钮。

请求为私有 UI 的严格恢复意图，绑定完整原稿、所属顶层步骤和单调修订；共享后端 DTO 不变。取消、无效、拒绝、异常、非严格同步 true 回执均保留填写。确认后只清被接收的返工修订，较新同类填写与其他未应用类型不得被旧回调清除。真实父层继续执行输入来源、模型结果、容量等完整语义校验，原撤销/重做和 saveWorkflowAction 保存链路不变。
