# Harness 后端执行边界

这是 V5.7 Harness 向云版迁移的第一条运行时链路。现有云版的交付质量检查和有限自动返工继续生效；新增检查覆盖模型与工具步骤的执行出口。

## 策略判定

`HARNESS_POLICY_JSON` 是服务端配置，格式为 `{"version":1,"rules":[...]}`。规则可指定 `nodeType`、`nodeId`、`registryToolId`、`scope`、`risk`，各条件按精确值匹配。`effect` 为 `allow` 或 `deny`；多条规则命中时，拒绝优先。不配置时沿用现有执行行为，配置格式错误时阻止模型与工具步骤。每次裁决写入 `harness.policy` 轨迹，只记录裁决、规则编号和节点类型，不保存提示词或凭据。

当前策略只支持允许与拒绝。需要人工确认的业务动作仍应在流程中使用已有人工确认节点；不能用允许规则越过该节点。

## 上下文预算

模型调用前检查步骤名称、目标、上游成果、任务输入和质量反馈。任一必需部分将被提示词组装逻辑截断时，调用立即失败，不发送不完整提示词。`HARNESS_MAX_PROMPT_CHARS` 可将系统与用户提示词合计预算设为 1000～120000 字符；不配置时为 120000。检查结果写入 `harness.context` 轨迹，只记录字符数与是否通过。

这是字符预算，不是模型 token 或费用上限。现阶段未移植 V5.7 的工作区策略编辑、人工策略审批、计划快照、记忆治理和策略模拟。这些能力需要独立的持久化契约与执行链验证，不能仅凭现有质量节点宣称已完成。
