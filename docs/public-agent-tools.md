# 公开助手工具最小后端

公开工具把已通过发布门禁的助手版本提供给持有独立调用凭据的程序。公开调用不等于匿名执行；Auth.js 登录仍后置，管理操作单独校验服务器配置的管理员凭据。本版只支持现有固定演示工作区，服务器拒绝其他工作区，不能宣称已经实现组织登录或通用多租户授权。

定义、发布、停用和凭据撤销均限定本工作区。发布必须明确选择状态为 production 的版本，并冻结助手标识、版本标识、版本序号、manifest 指纹及输入/输出字段契约。新发布助手版本不会改变工具绑定；被 retired 的原版本仍可按原发布绑定执行，candidate、superseded、缺失或内容变化的版本不能调用。

调用复用 startRunCore 的 versionId、资源准入、Workflow 编排、模型和业务工具防重；sourceType 保持 manual，sourceKey 为 public-tool:<工具标识>:<请求标识>。独立调用记录注明来源并冻结本次发布绑定和等价输入摘要。调用方必须在首次发送前持久保存 UUID 请求标识；重试沿用同一标识和输入，工具后续重新发布也不会让原调用跳版。不同工具有独立请求键空间，凭据轮换不会改变请求归属。

接收回执只表示服务器登记了异步业务请求，不能证明已经启动、执行成功、对外送达或严格一次副作用。启动结果未知时只允许同一次请求核对和重试，禁止自动创建新请求。成功业务结果只从已 completed 的原运行读取，失败、取消、等待及未知状态不返回过程成果。读取有界结果不等于接收方已经持久保存结果；首批不接收自定义回调网址，不代替已有成果投递协议。

调用密钥使用 32 字节随机数，仅保存 SHA-256 摘要，明文只在成功创建时返回一次；提交响应丢失后同一请求只能找回无明文的密钥元数据，需撤销并用新请求创建替代密钥。密钥限定一个工具、本工作区及可选到期时间。列表、审计、错误和业务回执不包含密钥明文或摘要；内部 manifest 摘要和流程指纹也从公开定义中投影移除，公开版本视图从同一发布契约派生。停用工具或撤销密钥拒绝后续认证，包括结果读取；已通过事务接收的请求可能继续执行，这不是取消运行功能。

管理 API 使用 PUBLIC_AGENT_TOOLS_ADMIN_TOKEN 环境变量，至少 32 个安全字符；未配置或非法时关闭管理入口。使用 Authorization: Bearer 传递管理或调用凭据，不接收查询字符串、JSON 或 cookie 中的凭据，不把调用凭据发给模型或业务工具。管理请求拒绝跨站浏览器请求，调用入口不提供 CORS；服务器程序不需要伪造浏览器 Origin。部署访问保护仍由部署管理员配置。

HTTP 入口：

- GET/POST /api/public-tools：管理员列表/定义。
- POST /api/public-tools/<工具标识>/manage：管理员发布、停用、发放或撤销密钥。
- GET /api/public-tools/<工具标识>：调用凭据读取安全定义及已冻结字段。
- POST /api/public-tools/<工具标识>/calls：调用凭据提交 { requestId, input }。
- GET /api/public-tools/<工具标识>/calls/<请求标识>：同工具有效凭据读取异步状态和成功成果。

共享请求和回执唯一来源为 contracts/public-agent-tool.ts，输入沿用 100KB、12 层、2000 项，HTTP 总请求 104KB；管理请求 8KB；最终成果沿用 2MB、32 层、50000 项，整体回执 2MB + 16KB。检测到凭据正文拒绝执行或展示，不能通过脱敏改变已冻结契约的业务含义。结果非法、超限或运行关联不完整时返回未确认，不冒充成功。调用记录不保存输入正文或模型/工具密钥。

数据库只新增 public_agent_tools、public_agent_tool_keys、public_agent_tool_calls、public_agent_tool_changes 的 Drizzle 定义；迁移由中央 CI 顺序使用 drizzle-kit 生成，未生成/应用迁移前本能力不可用。所有记录具备 workspace_id、created_by、created_at、updated_at；管理变更和请求记录永久保留防重，不复用已归档工具的请求键。

未覆盖能力：用户登录、组织角色与 RLS、分调用方结果隔离、IP/每分钟请求限流、独立工具费用预算、完整提示词攻击防护、自动取消已接收请求、成果推送、完整副作用对账、用户网页和自定义域名托管。现有业务资源名额和模型调用额度仍生效，不能把它们宣称为 HTTP 限流。有效工具凭据可以读该工具的所有调用结果，应按业务隔离要求分别定义工具。

验收源码包含纯领域/契约、服务与动作/路由 mock、隔离数据库和真实 Workflow 回归；数据库与 Workflow 套件须由 CI 配置 MVP_ACCEPTANCE_ISOLATED_DB=1 且指向临时空库，使用本地模拟模型或工具，不能指向共享或生产库。本工作批次均未运行，安装、类型、lint、单测、构建、迁移、真实部署与真实业务验收仍待中央 CI/人工配置。

两套隔离回归在检查通过后才动态加载数据库与服务，检查失败或加载未完成不进入删除流程。SDK4 的取消回执和运行终态不能证明在途步骤或后台生产者退出；Workflow 套件只对自有句柄做总计三秒内的观察与尽力取消，不做全局停止。已启动 SDK 或存在未结束测试请求时保留本批记录并明确阻断自动清理，包括根返回值已自然成功但没有生产者退出证明的情况。因此该 Workflow 套件的安全清理验收仍是阻断项，不能虚报可全绿；需由中央隔离执行器另行提供生产者退出证据后再清理临时库。
