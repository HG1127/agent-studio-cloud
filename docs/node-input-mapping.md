# 模型、知识、业务工具与多助手字段映射

智能处理、业务判断（不含确定性质量检查）、知识检索、工具以及调用/交接助手步骤支持共享契约中的 `inputMapping`。配置可经助手定义导入或后端流程保存；目前画布没有专门的映射编辑入口，长期经验步骤尚未启用该配置。未配置映射的旧模型与工具节点继续接收原任务输入和上游结果，旧协作节点保留已有上下文生成行为，旧知识节点保留固定内容、循环项和原任务的检索优先级。

## 配置示例

以下节点输入来自任务客户编号、某一步的结构化金额和一个固定标记：

```json
{
  "inputMapping": {
    "includeUpstreamOutputs": false,
    "fields": [
      {
        "target": ["customer", "id"],
        "source": { "kind": "input", "path": ["customerId"] }
      },
      {
        "target": ["amount"],
        "source": { "kind": "output", "nodeId": "extract", "path": ["amount"] }
      },
      {
        "target": ["approved"],
        "source": { "kind": "literal", "value": true }
      },
      {
        "target": ["note"],
        "source": { "kind": "input", "path": ["note"] },
        "required": false
      }
    ]
  }
}
```

任务 `{"customerId":"c1"}` 和提取结果 `{"amount":123.5}` 会得到 `{"customer":{"id":"c1"},"amount":123.5,"approved":true}`。模型首次调用及格式修正都只使用这份映射输入。工具仍使用已有 HTTP 信封格式：

```json
{
  "action": "record",
  "input": { "customer": { "id": "c1" }, "amount": 123.5, "approved": true },
  "outputs": {}
}
```

工具对映射后的完整信封校验冻结和当前服务端输入契约，校验通过才发出请求。不得把映射误当成关闭工具契约、改变服务端权限或地址的方式。

## 字段含义

- `target`：目标路径数组，构造嵌套对象。目标层级最多 12 层，每段最多 100 个字符；重复目标或祖先/子孙覆盖均拒绝。数字目标段仍是对象字段名，不自动构造数组；需要数组时映射整个数组或使用固定数组。
- `source.kind`：`input` 读取原任务输入；`output` 读取指定步骤的业务结果；`literal` 使用固定 JSON 值。
- `source.path`：来源路径数组，默认空数组表示读取整个来源值。支持数组索引，如 `["orders","0","id"]`，最多 32 段，每段最多 200 个字符；只读自有属性，不访问对象原型。
- `source.nodeId`：输出来源的真实步骤标识，最长 200 个字符；内联步骤使用完整标识，如 `group.extract` 或 `batch.branch.extract`，不按点号拆开。字段路径用数组，可以直接读取 `["customer.id"]` 这样的业务字段名。
- `required`：默认 `true`，缺失来源则在步骤执行前失败。设为 `false` 时仅省略缺失字段，不猜测业务值。
- `fallback`：显式缺失兜底值；只有来源为未定义或不存在时才使用，`null`、`0`、`false` 和空字符串保持原值。固定值及兜底值均必须是合法 JSON，单个最多 64KB。
- `includeUpstreamOutputs`：显式映射默认 `false`，不额外传整份上游成果；模型和工具设为 `true` 会携带全部上游结果。知识检索与助手协作不能开启该选项，必须逐项映射需要的字段。

## 知识检索字段映射

知识节点可以选择上游已提取的业务主题，不必把整份原任务当作检索词。主流程、顺序子流程、并行内联步骤和循环均使用同一映射机制；内联来源使用完整步骤标识，循环当前项可从循环步骤回执的 `currentItem` 字段选择。以下配置不会采用旧固定内容、原任务的另一问题或未选择的上游成果：

```json
{
  "id": "lookup", "title": "按业务主题查阅", "type": "knowledge",
  "knowledge": { "space": "售后资料", "query": "旧的固定内容" },
  "inputMapping": {
    "fields": [{ "target": ["query"], "source": { "kind": "output", "nodeId": "extract", "path": ["topic"] } }]
  }
}
```

```json
{
  "input": { "question": "不是最终检索主题" },
  "outputs": { "extract": { "topic": "退货政策" }, "other": { "text": "不应附带的其他成果" } },
  "currentItem": { "question": "其他循环主题" }
}
```

本例的实际检索词是“退货政策”。明确映射的 `query` 必须是非空文字（最多 1000 个字符）或有限数字；数字零保留为 `"0"`，编号文字的前导零不丢失，不把布尔值、数组或对象隐式转换成数字。字段存在但值为 null、空白、布尔值或超限时明确失败，即使其他映射字段有内容也不替代它；不会截断明确检索词后悄悄改变主题。需要缺失兜底时应配置 `fallback`，不能依赖旧固定内容或原任务自动补上。

未映射 `query` 时，可显式组合多个业务字段，继续使用既有有界检索拼接：优先读取问题、查询、任务等文字字段，否则汇总嵌套文字与有限数字，去重、最多 32 项、每项最多 200 个字符，最终最多 1000 个字符；布尔值不形成检索词。映射后为空则失败，全部可选字段缺失也不回退整份原任务。已识别的凭据字段或凭据文字在查询前拒绝，不以脱敏改写检索含义，失败说明不包含原始正文。

知识检索不接受 `includeUpstreamOutputs: true`。映射只影响查询内容，不解释映射字段中的资料范围、工作区或空间配置；实际来源仍由节点选择、发布版本的 `knowledgeSnapshot` 与运行所属工作区共同限制，不读取未发布、已归档或其他工作区资料。回执沿用原字段，由 `contracts/knowledge.ts` 的 `KnowledgeReceipt` 统一定义；本轮没有向量检索、新凭据、迁移或专用画布编辑器。

## 多助手协作

调用和交接助手按映射构造精确的子运行输入，保留数字、布尔、数组和嵌套对象类型；不会额外添加上下文，也不会把缺失的字符串字段自动填成整份上下文。创建子运行前同时校验冻结的接收助手输入契约；交接还校验交接输入契约。缺少来源、类型不符或存在未声明字段时明确失败，配置备用路径的节点进入备用处理，不创建子运行。

协作来源数据先经过已有脱敏规则，映射后再次脱敏，避免通过重命名、固定值或兜底值绕过边界。交接中的禁止内容及私有字段规则继续生效。未选择团队共享模式时，长期经验读写回执即使藏在顺序子流程、并行结果或数组内，也不进入子运行；数组保留原位置，移除的经验回执置为空，不让索引指向其他记录。团队模式允许显式选择经验字段，但仍脱敏。

这些规则不能识别已经失去来源标识的任意业务文字，也不替代使用者对所选信息的审查。旧协作上下文同样应用嵌套经验隔离，防止容器包装绕过既有共享策略。

## 循环、内联流程与边界

### 完成后引用内部成果

根流程或其他容器中的后续模型、工具、知识、调用助手和交接助手，可以直接以完整内部步骤标识引用已完成的成果。例如来源 `{ "kind": "output", "nodeId": "group.extract", "path": ["rows", "0", "amount"] }` 表示冻结顺序子流程 `group` 中 `extract` 的业务字段；并行来源可以使用 `batch.research.extract`。标识中的点属于完整标识，不拆点推测分支、步骤或字段名；子步骤同名时按冻结位置读取，不按标题匹配。

来源定位仅由运行时冻结的流程图生成，单步只携带其映射字段及业务防重键真正引用的定位；不是用户可提交的业务数据，不进入模型提示词、工具 HTTP 正文、持久上下文或最终成果。顺序子流程只读取完成汇总；并行只读取完成或带问题完成汇总中的成功分支，失败、未结束和半成品不冒充成功成果。完整内部来源同样可用于 `toolOperation.key`，保留零值和编号文字。

容器正在执行时，本次已经完成的本分支步骤仍通过原平铺上下文读取；该容器的汇总定位全部排除，避免读取上次循环/返工成果或尚未完成的兄弟分支。结束后的定位不复制业务正文，不改变原有子流程 `steps`、并行 `branches`、全量上游上下文或默认最终交付的结构。缺失继续遵循必填、可选和显式兜底规则；协作仍先应用脱敏和经验共享策略，定位不能恢复已移除的数据。不会递归扫描任意模型对象寻找看似容器的成果。

字段试算接口不加载冻结流程或真实运行：要试算内部来源，样例 `outputs` 仍需以完整步骤标识提供对应成果；请求不能注入内部 `inlineReferences` 定位。它不替代真实容器执行和发布验收，暂无专用画布配置入口。

循环体可从循环步骤输出读取 `["currentItem","id"]`，每一项都读取当次循环回执。顺序子流程及并行分支内的模型、知识和工具步骤使用相同解析逻辑，可读取已完成的本分支步骤或父流程成果。不同并行分支不会自动共享尚在执行的结果。

保存、导入、发布、恢复和运行启动时拒绝不存在的来源步骤。引用存在不代表结果已生成：来源步骤尚未执行、被条件跳过或执行失败时，仍按必填、可选和显式兜底规则处理。不要用未来步骤作为无兜底的必填来源。

每个节点最多 100 个映射字段。映射后的输入遵循运行输入约束：UTF-8 JSON 最多 100KB、最多嵌套 12 层、最多 2000 项、最多 100 个顶层字段，禁止保留字段名、非有限数字、函数、日期对象和循环引用。超限明确失败，不静默截断或把不合法值转换成空值；所选对象会复制，不修改原任务或其他分支。若显式保留全量上游结果，工具原有 512KB 请求体上限仍生效。

模型与工具字段映射不会自动识别业务秘密；明确选中的字段会按配置传递。服务端工具凭据仍只在注册表中保存，不能从任务上下文读取。请仅选择本步骤真正需要的业务信息；多助手协作额外遵循上述脱敏及经验共享边界。
