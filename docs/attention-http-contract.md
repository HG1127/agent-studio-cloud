# 集中待处理 HTTP 约定

`GET /api/attention` 为现有受保护部署中的操作员提供跨任务异常与等待摘要。共享结构唯一来源是 `src/contracts/attention.ts`；登录权限仍后置，接口不是开放公网入口。不要关闭部署访问保护。

## 清单范围

| `kind` | 纳入条件 | 详情与处理 |
|---|---|---|
| `approval-pending` | 任务正在等待审批，记录仍待决定且未消费 | 读取完整成果后，通过既有审批接口明确决定 |
| `approval-resume` | 任务正在等待审批，决定已保存但未消费 | 核对原决定，按原请求恢复，不跳过新的审批 |
| `wait-event` | 任务停在等待节点，包括定时等待与外部消息等待 | 按 `timing.waitMode` 区分；定时等待不要求提交消息，方式未知时先核对任务 |
| `run-failed` | 任务执行失败 | 查看原因与轨迹，核对外部副作用后决定是否重新运行 |
| `tool-operation` | 持久业务操作处于待核对状态 | 通过原核对入口记录回执或明确确认未执行后允许重试 |
| `delivery-failed` | 未归档的成果投递失败 | 核对接收结果、原正文和固定有效期后决定是否补投 |

同一个任务可以包含多个独立事项。例如业务任务已经完成，成果投递仍失败，不能因此把任务改成失败或重新执行模型、工具。已消费旧审批、终态任务上的审批、正常执行、正在自动重试的投递和已归档投递不混入人工清单。已归档助手的历史异常仍可查到。

清单是实时状态查询，本身不改写业务状态：失败任务保留历史终态，没有自动关闭操作；独立持久跟踪支持接手、备注、明确关闭和重开，但不能绕过原业务处理，完整约定见 `docs/attention-handling-http-contract.md`。时效分类仅提示排查，不发送提醒或宣称完成超时告警。独立业务操作的来源任务缺失或不在同一工作区时，仍可核对操作本身，关联的助手名称与任务状态为 `null`，不会猜测或跨工作区读取。

## 筛选与稳定翻页

可选参数为 `kind`、`agentId`、`runId`、`timingState`、`handlingState`；`limit` 默认 20、最大 50。处理状态为 `open`、`in-progress`、`closed`，筛选先于分页；默认不隐藏关闭跟踪后的失败任务。助手与任务标识按 UUID 小写归一化。不能指定工作区、任意查询字段或正文；未知参数、重复参数、非法标识与容量拒绝为 `400`。

```text
GET /api/attention?kind=delivery-failed&limit=20
```

返回 `ok: true`、`items` 与 `nextCursor`。每项包含类别、来源标识、关联助手与任务状态、标题、脱敏错误、创建时间、中文处理提示及原记录的 `links.view/detail`；新增 `occurrence` 标记与 `handling` 状态、版本和条数摘要，旧客户端可忽略。发起处理须原样携带最新本次标记，新一轮等待或失败不会继承旧关闭状态。不批量返回输入、上下文、结果、审批正文或备注、处理历史正文、业务回执、投递正文、接收网址、请求指纹、密钥、Hook token 或引擎句柄。标题、助手名和错误均有容量边界，超过摘要容量时明确设置对应 `*Truncated`，截取保留完整 Unicode 字符，不拆开表情符号。数据库截掉私钥结束标记、短凭据或地址末尾分隔符后，摘要仍保守隐藏凭据式片段；原始业务记录不因此改写。完整业务成果只在原详情接口读取。

按来源记录的创建时间、标识、类别倒序；这不是等待开始时间、异常发生时间或超时判定。数据库微秒原样返回，类别使用固定字节序，避免不同来源使用相同标识、时间时丢项。下一页须保持原筛选，并同时传入：

```text
before=<nextCursor.createdAt>&beforeId=<nextCursor.id>&beforeKind=<nextCursor.kind>
```

三个字段不得省略任一项，不要通过 JavaScript Date 转换后截断微秒。清单不使用偏移量翻页。新插入的更晚记录不挤入旧游标后续页，但并发状态变化可能让事项退出或变换类别；处理后应刷新首页，不能把多次实时读取当成冻结历史快照。

## 可信时效分类

新增 `timing` 由 `src/contracts/attention-timing.ts` 定义，旧返回结构仍兼容。`waitMode` 为 `event`（外部消息）、`timer`（定时）、`none`（非等待节点）或 `unknown`；`sinceAt` 是可信状态起点，`expectedAt` 是本次等待配置的预计时间，`retryDeadline` 是业务操作或投递既有防重截止，缺失时明确返回 null。`assessedAt` 是本次统一检查时间，`elapsedSeconds` 只在起点有效且不晚于检查时间时返回，否则为 null。原始轨迹和内部毫秒字段不返回。

`timingState` 在数据库分页前筛选，取值与优先级如下：

| 值 | 判定 |
|---|---|
| `retry-expired` | 原防重截止已到，优先级最高；此分类不能重新开放重试 |
| `expected-overdue` | 预计时间已过至少 30 秒，应排查执行状态 |
| `long-pending` | 有可信起点，审批、外部消息或非定时异常持续至少 24 小时 |
| `unknown` | 起点缺失、晚于检查时间、等待方式未知，或定时等待没有可支持的预计时间 |
| `normal` | 其余情况；正常长定时等待不因超过 24 小时而被标记久等 |

等待起点取本工作区本任务最新 `wait.started` 轨迹，不用任务创建时间冒充，也不使用其他工作区轨迹。新等待步骤保存模式与预计时间快照；旧事件轨迹可凭已有事件标记识别，旧无标记定时记录保留 unknown，不猜测为外部消息。审批使用创建时间，审批待恢复使用决定时间，失败任务使用完成时间，业务核对和失败投递使用各自更新时间。缺失历史时间不做推测性回填。

预计时间是进入等待时的配置快照，不声称等同于引擎恢复时间；相对定时与事件超时真正从工作流执行等待后起算，保存快照与调度有延迟，故保留 30 秒提示宽限。分类不改变 Hook、定时、超时分支或任务终态，不自动取消、恢复、延长防重期限或重复业务写入。可展示时刻支持公历 0001 至 9999 年；超范围历史值按未知处理，不因此改变原有合法等待执行语义。

```text
GET /api/attention?timingState=expected-overdue&limit=20
```

## 错误与边界

跨站来源或 `Sec-Fetch-Site: cross-site` 返回 `403`。未知存储故障、无效元数据或不符合共享契约的结果返回 `503`、`retryable: true`、`Retry-After: 2`，不返回伪造空成功清单，也不回显原始存储错误。所有响应为 `Cache-Control: no-store`。

本接口只读，不恢复工作流、不调用业务工具、不补投、不新建运行、不覆盖审批决定。所有写操作仍经原 Server Action 与各自确认、防重和补偿规则执行。前端专用集中处理页面由独立前端工作对接，本轮不修改布局、组件或样式。

来源索引由 `0028_attention-query-indexes.sql` 提供，独立处理记录及索引由 `0029_attention-handling-records.sql` 提供，只追加迁移，不修改旧文件。生产迁移与受保护环境访问验收按人工配置清单执行。
