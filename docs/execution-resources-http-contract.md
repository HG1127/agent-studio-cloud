# 执行资源准入与设置

此能力只用于已有访问保护或受控部署，不新增登录、外部身份凭据或前端设置页面。所有共享字段由 `src/contracts/execution-resources.ts` 定义。默认无需新增环境变量，生产先应用 `0033_execution-resource-admission.sql`，不能把构建成功当作迁移完成。

## 限制与准确口径

- 默认最多保留 50 条业务执行链，每条链最多登记 200 次模型调用、创建 100 个协作子任务。支持范围分别是 1–2000、1–10000、0–199；零协作额度表示禁止创建子任务。
- 并发名额按业务运行状态保留，不是供应商瞬时网络请求数。排队、执行、审批和等待都占名额；主任务结束但子任务仍活跃时不提前释放。所有成员结束后自然释放，无需另外删除记录。
- 只有可确认的本工作区根、根的自身归属、根类型和相同冻结快照才合并名额。历史无资源归属、缺失或外工作区根、部分或冲突元数据各自保守占位；未知状态也占位，不转为结束。
- 新根冻结模型和协作上限、设置版本及覆盖标记，子任务继承同一快照。后来调整设置只改变新根的链内限制；工作区名额限制立即用于新根准入，降低上限不取消已接收任务，也不修改既有快照。
- 模型在供应商调用前、子任务在创建前进行事务准入。模型意图包括 SDK 内部重试、格式修正和循环，失败、未确认及归档记录不退还次数；结果补记不再消耗额度。所有网络 I/O 在事务外。
- 同一根请求或协作来源请求先找回已有任务，再检查新任务额度；不会因为名额已满重复创建或拒绝合法的原请求找回。资源归属或完整关系不可信时不启动新的模型调用或协作创建；此准入不是其他分支维护的工具授权策略。
- 历史链首次受控操作采用 `legacy-or-partial`，只统计已登记意图，不伪造早期供应商记录，不回填模型或父关系覆盖声明，也不刷新旧启动租约的更新时间。历史未记录的真实调用不可恢复，因此不是历史全生命周期费用或次数账单。
- 每次模型或协作准入最多读取 200 个运行、深度 8；缺失祖先、环、关系冲突、未知状态、资源快照损坏或图超限时永久停止新的模型调用与协作创建。只有持久数据库暂时故障允许安全重试，不自动扩大额度。

## 读取当前设置与名额

`GET /api/execution/resources` 不接受查询参数或正文。只读可重复读事务提供同一时点的设置和名额，不为默认值创建数据库记录。示例：

```json
{
  "ok": true,
  "snapshot": {
    "policy": {
      "revision": 0,
      "source": "default",
      "limits": { "maxConcurrentChains": 50, "maxModelCalls": 200, "maxChildRuns": 100 },
      "updatedAt": null
    },
    "capacity": { "reservedChains": 0, "untrackedActiveRuns": 0, "availableSlots": 50 },
    "assessedAt": "2026-10-09T12:00:00.000Z"
  }
}
```

`untrackedActiveRuns` 表示未能按可信资源归属合并的活跃记录，不是缺失供应商用量的估算。查询不返回任务正文、根标识、工作区、创建人、秘密或价格。设置损坏或已停用时安全拒绝，不能回退默认限制继续执行。

## 明确修改设置

`POST /api/execution/resources` 要求同源 JSON，不接受额外查询参数，正文最多 16KiB。写入唯一入口是 Server Action，不能传工作区或创建人：

```json
{
  "requestId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
  "expectedRevision": 0,
  "confirmed": true,
  "limits": { "maxConcurrentChains": 10, "maxModelCalls": 20, "maxChildRuns": 5 },
  "reason": "业务试点采用较低资源上限"
}
```

规范化请求标识、版本、限制和脱敏原因组成原请求依据。同一请求重复发送只找回原记录；修改内容或版本返回 409。不同请求修改同一旧版本只允许一方提交，设置和追加历史在同一事务保存。每个新请求即使限制相同也记录新版本及原因，不覆盖旧历史。原因在保存和读取时隐藏常见凭据。

```json
{
  "ok": true,
  "recordedRevision": 1,
  "policy": {
    "revision": 1,
    "source": "configured",
    "limits": { "maxConcurrentChains": 10, "maxModelCalls": 20, "maxChildRuns": 5 },
    "updatedAt": "2026-10-09T12:00:00.000Z"
  }
}
```

`recordedRevision` 始终是这次原请求登记的版本；`policy` 是当前有效设置。原请求在后来修改后重发会返回原记录版本和更新后的当前设置，不重新施加旧限制。保存或响应结果不确定返回 503、`retryable: true`、`Retry-After: 2`，必须沿用原请求，不另造请求标识。

## 追加历史

`GET /api/execution/resources/history?limit=20&beforeRevision=3` 按版本严格降序，默认 20、最多 50 条。`beforeRevision` 是排他游标，首页省略。未知、重复及非法参数返回 400。新修改不会挤入旧游标后续页；不存在设置时返回空历史，不新增记录。

```json
{
  "ok": true,
  "items": [{
    "id": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb",
    "requestId": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
    "revision": 1,
    "previousLimits": { "maxConcurrentChains": 50, "maxModelCalls": 200, "maxChildRuns": 100 },
    "limits": { "maxConcurrentChains": 10, "maxModelCalls": 20, "maxChildRuns": 5 },
    "reason": "业务试点采用较低资源上限",
    "createdAt": "2026-10-09T12:00:00.000Z"
  }],
  "nextBeforeRevision": null
}
```

历史仅返回公开字段，不返回请求哈希、工作区、创建人或原始凭据。已登记请求不会因软归档被重新应用；历史不提供删除或覆盖入口。

## 执行拒绝与部署

任务提交沿用现有 `/api/runs`。新根名额满返回 429，而不是接收成功或一般业务冲突：

```json
{
  "ok": false,
  "error": "当前执行链已达到并发上限，请等待已有任务结束后使用原请求重试",
  "retryable": true,
  "resourceLimit": { "kind": "concurrent-chains", "current": 10, "maximum": 10 }
}
```

响应带 `Retry-After: 2`。未建立运行和投递意图，不启动引擎；手动、定时和验收共用根任务准入。已接收原请求仍找回原任务。模型或协作额度满永久停止新的调用或子任务，失败步骤和任务保留明确中文原因，已有真实调用记录不删除。

手动运行与再次运行的服务端动作保留同一 `resourceLimit`、中文原因及可重试标记，现有页面显示限额原因并保留原请求，而不是误报网络故障或启动结果不确定。真正提交状态不确定时仍沿用原待确认路径，不把未知结果当作明确拒绝。

批量验收先查原样例的运行是否已登记；已有运行继续按实际状态对账。确认因容量限制尚未建立任务的样例保留在原轮验收中，不记成执行失败、不越过质量门禁，明确提示等待名额释放后点击“检查并继续”。继续操作沿用原轮标识和样例来源键，不重复创建已接收任务；全部结果实际通过后才允许候选版本上线。这是明确继续入口，不是自动排队调度保证。

全部接口 `Cache-Control: no-store`。跨站读取/写入返回 403；格式错误 400，非 JSON 写入 415，超限 413，设置版本冲突 409，暂时故障或坏记录安全 503。不得为接入关闭部署访问保护。

本批不实现货币预算、全站账单、令牌硬预算、供应商并发保证、前端设置台或自动告警，不修改模型连接及定时配置。真实供应商计费、受保护部署访问与生产迁移仍需人工确认。数据库并发和实际 Workflow 的内部重试、格式修正及协作限制只在隔离 CI 写库验证。
