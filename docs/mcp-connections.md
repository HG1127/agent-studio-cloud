# MCP 连接检查后端

本线仅修改连接契约、领域纯函数、查询、只读检查工具、接口、测试和本说明；协议一致性修复复用调用核心的共享容量和定义契约，执行注册表配置来源与业务调用格式保持不变。不修改页面、模型连接或定时配置。

## 登记与发现

管理员仍通过服务端 `TOOL_REGISTRY_JSON` 登记；没有新的连接配置来源，没有浏览器登记地址/凭据入口。只检查 `protocol: "mcp-streamable-http"` 的登记项。MVP 每个已登记工具是一个检查入口，连接标识就是其 `registryToolId`，即使同一地址有多个工具也分别检查，保证不同凭据不会串用。工作区使用现有演示工作区，其他工作区不返回登记且不连接。

`GET /api/mcp/connections` 返回 `{ connections: [{ id, name }] }`。只投影管理员名称与内部选择标识；UI 应展示中文名称，内部标识不应显示给用户。响应禁止缓存。

`GET /api/mcp/connections/configuration` 是新增的零网络配置诊断入口，返回 `{ status, message, connections: [{ id, name, status, message }] }`，共享契约是 `McpConnectionConfigurationResult`。旧列表的严格响应结构不变，不在旧接口追加字段。响应禁止缓存，错误配置也是 200 的诊断结果，不冒充在线连接检查。

- `not-configured`：没有连接登记；缺失、空白、合法空数组或只有其他协议的合法工具都属于此状态。
- `configured`：所有连接登记通过本地配置校验；中文说明明确尚未检查远端服务，不代表地址可达、凭据有效、目录匹配或业务成功。
- `partially-configured`：至少一项配置有效和一项因额外连接限制无效，逐项保留安全名称与状态，不隐藏其他合法连接。
- `configuration-error`：核心工具注册表整体无效时返回空登记及固定中文说明；若核心合法但全部连接因额外限制无效，则保留这些诊断项。

状态与私有登记来自同一份缓存解析快照，不再用“原始配置非空且目录为空”推测错误。合法 `[]` 不输出错误日志，按标识检查返回未找到；非法 JSON、重复标识、安全边界失败仍整份拒绝，不泄露原始错误、地址、凭据、字段定义或配置正文。其他工作区在读取全局快照前隔离；单项状态只是本地登记校验，实际远端核对仍需下面的检查接口。此接口没有新增浏览器配置写入或页面，人工服务端配置要求不变。

2026-10-09 配置状态补丁基于 `103d358be283e67ac1092571cf40316f6b0f967a`，独立分支 `codex/mvp-mcp-configuration-state`。先用纯测试复现合法空数组的错误日志与检查误判，再补静态诊断契约、真实注册解析的虚构配置查询、纯投影及新旧接口回归。联合原有 MCP 协议、安全元数据、完整名称、检查和调用回归，共 16 个文件 180 项通过；全仓类型检查、13 份改动代码的严格 lint 和差异检查通过，均串行限制内存。只使用虚构配置及本机假 MCP 服务，未运行真实数据库、Workflow、E2E、构建、完整 CI 或真实供应商验收；局部结果不能累加或代替新的最终组合提交完整门禁。

`POST /api/mcp/connections/check` 只接受严格 JSON `{ connectionId }`（最多 1KB），必须带与请求地址一致的 Origin。地址、凭据、工作区、任意附加字段均被拒绝。未知标识返回 404 且零网络。当前 MVP 无新增登录权限；后续 Auth.js 接入需将演示工作区改成服务端认证上下文，不接受浏览器工作区覆盖。

检查结果是 `{ status, message, tools: [{ registryToolId, name, status }] }`，定义见 `src/contracts/mcp-connection.ts`。总体状态区分 `available`、`credentials-rejected`、`protocol-error`、`unavailable`、`definition-changed`、`not-found`、`configuration-error`。目录缺失、输入定义漂移均标记不可用；可用只表示握手与登记定义核对通过，不代表执行成功、写入防重或业务授权已经验证。

## 安全与协议边界

- 使用核心锁定的官方 `@ai-sdk/mcp` 2.0.73，不升级依赖树；与执行客户端一样先用只读 `server/discover` 协商，再由 SDK 在不支持发现时回退旧握手，关闭自动重试，不配置 OAuth。支持该版本 SDK 已实现的新旧协议，不声称支持所有 MCP 扩展或额外输入交互。
- 实际协议请求只允许 `server/discover`、`initialize`、`notifications/initialized`、`tools/list`；另允许 SDK 对服务端心跳发送严格的空结果回复，结构由 `McpPingResponse` 定义，只含 jsonrpc、原请求编号和空 result，不带参数、方法或错误正文。绝不调用 `tools/call`，不开放采样等额外 JSON-RPC 方法。发现阶段仅允许 HTTP 400/404/405/406/415 的旧协议协商回退，凭据拒绝、限流、服务器错误及传输越界立即停止，不通过回退重试这些故障。SDK 的独立 GET 事件订阅在本地返回 405，检查不订阅服务端事件；POST 响应携带的 SSE 仍由 SDK 解析。
- 沿用执行注册表的 HTTP/HTTPS 地址约束，禁止 URL 用户密码，兼容管理员已登记的本机 HTTP 与查询参数；登记地址经 new URL(endpoint).href 规范化后作为固定传输目标和唯一比较基准，兼容根地址尾斜线和主机大小写，不接受其他目标或重定向。Cookie、代理凭据、Host 与连接控制头等配置被拒绝；请求明确省略浏览器凭据，移除 Cookie 与业务防重头。管理员必须登记可信服务地址。单项额外检查限制（如 Cookie 头、定义容量）仅使该登记项返回 configuration-error，不隐藏其他合法连接；核心注册表整体无效时沿用其整体拒绝策略。
- 检查时限 10 秒，会话关闭另限 1 秒；与执行共用 `MAX_MCP_TRANSPORT_REQUESTS` 的 32 次输送请求预算，计入协商、SDK 的 GET 尝试、目录分页和心跳回复，检查另允许 1 次会话关闭请求。支持五页目录每页一次心跳，超额心跳仍停止；不增加 SDK 重试。与执行共享 5 页、每页 100 项、每个响应 1MB、总响应 4MB 边界。已登记输入定义与运行使用同一 32KB UTF-8 JSON 契约，越界配置只使该连接不可用并在网络前拒绝；远端未登记定义不冒充登记定义，不套用该 32KB 限制，但仍受目录和输送容量限制。拒绝分页游标重复、跨页名称重复、非法 UTF-8、超额和非法目录。原始错误、远端名称描述和未登记定义都不会进入响应或日志。
- 远端目录名称与内部连接标识分开：`McpRemoteToolName` 同时约束远端目录与已登记 MCP action，允许 1–128 位字母、数字、下划线、连字符和点，包括以下划线开头的名称。内部连接标识仍限 100 位及首位字母数字，HTTP 或未填协议的 action 仍限 100 位；不截断名称、不自动登记或开放其他工具。名称区分大小写，详见 `docs/mcp-registered-tool-names.md`。
- 只核对已登记 action 和输入定义，字段顺序不影响结果。现有注册表的 outputSchema 用于执行回执验证，不能当成远端必定声明的 outputSchema；检查不声称验证了实际回执。领域函数支持显式登记的输出定义核对，当前查询适配未启用。
- 本地回执定义在连接配置诊断和检查入口先做零网络预检；冻结绑定、导入回绑、发布及实际调用也复用同一纯校验。损坏或不支持的规则、明确不能返回对象的根类型、超过1MB实际JSON字节的定义会提前拒绝，不能等写操作完成后再发现本地规则不可执行。回执定义不套用参数的32KB上限；合法空规则、可空对象、组合和已有本地引用保持兼容。远端不声明回执定义仍可使用，既有实际回执校验保持；此预检不求解所有规则组合是否存在合法结果，也不证明远端业务可用。
- 检查结束关闭本地连接、取消读流；若 SDK 建立了会话，仅向相同登记地址发送一次限时 DELETE 关闭会话，清理失败不改变检查结论；连接检查不持久化业务数据，也不修改或自动新增执行登记。API 的可用结果只能作为绑定选择的提示，真正执行仍由核心调用时重新核对目录，防止检查之后的漂移。

## 参数定义提前检查

已登记 MCP 输入定义在连接检查、模板创建、冻结绑定与实际调用中复用同一纯函数：必须为被动 JSON、根 `type: "object"`、受支持的字段规则，序列化后的 UTF-8 JSON 不超过共享 `MAX_MCP_DEFINITION_BYTES`（32KB）。恰好达到容量和合法零参数对象仍通过；不执行访问器或自定义序列化，不截断、不补值。

冻结快照与当前登记相同不再代表一定可执行：无效定义在发布、启动和步骤复核前拒绝，实际调用在初始化或发现网络请求前拒绝。通用导入沿用可编辑语义，保留原定义但解除无法执行的绑定，要求重新选择工具；不会把无效工具当作已绑定保存。模板只检查选择的 MCP 工具，不因未选择的其他登记而失败。HTTP 输入信封及工具输出定义不套用此 MCP 输入容量限制，其他既有约束保持。
