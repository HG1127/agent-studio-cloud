# 业务工具 HTTP 接入约定

业务工具只从服务端环境变量 `TOOL_REGISTRY_JSON` 注册。工具地址、鉴权请求头不会写入助手草稿、版本或浏览器；画布只看到工具名称、用途和输入输出契约。

## 注册字段

- `id`：稳定且唯一的工具标识，只能包含字母、数字、点、下划线和短横线。
- `name`、`description`：画布上展示的中文名称与说明。
- `endpoint`：完整 HTTP(S) 地址，不允许在地址中携带用户名或密码。
- `method`：`POST`、`PUT` 或 `PATCH`，缺省为 `POST`。
- `headers`：仅服务端使用的鉴权请求头；最多 20 项，禁止换行。
- `action`、`scope`、`risk`：业务动作、权限范围和风险级别。
- `inputSchema`、`outputSchema`：受支持的 JSON Schema 子集。`inputSchema` 校验下面的完整请求 JSON，`outputSchema` 校验业务回执；任一不匹配时本次步骤失败，不会调用业务系统或把坏数据传给后续步骤。

字段使用 `pattern` 时，模式最多 200 个字符，同时必须设置不超过 4096 的 `maxLength`；不支持分组、分支或反向引用。每个模式最多允许一处可变长度数量规则（`*`、`+`、`?`、`{m,n}` 或 `{m,}`）；固定数量 `{n}`、上下限相同的 `{n,n}`、字符范围里的符号和转义的字面符号不占用这一限额，懒惰匹配后缀也不额外计数。复杂格式请拆分字段或改用固定数量，例如 `^[A-Z]{2}[0-9]+$`。这项限制避免短消息触发长时间回溯。

## 请求

系统发送 JSON：

```json
{
  "action": "update_customer",
  "input": { "customerId": "c1" },
  "outputs": { "review": { "approved": true } }
}
```

请求头包含 `Idempotency-Key: <运行标识>:<步骤标识>:<本次执行标识>`。同一次步骤因瞬时失败重试时会复用这个键；循环再次执行同一画布步骤时会换用新的键。外部系统必须按此键保证单次步骤执行的重复请求只产生一次业务副作用。请求体上限为 512 KB，调用超时为 30 秒，并禁止自动跟随重定向。

## 回执与失败

成功响应必须是 UTF-8 编码的 JSON 对象，最大 1 MB，数据值最多嵌套 32 层、包含 50000 项。空成功响应会规范化为 `{ "ok": true }`；非空响应通过字段契约后，系统也会在内部补充 `ok: true` 供回执门禁统一判断。外部响应若包含 `ok` 字段，必须为布尔值 `true`；`ok: false` 表示业务操作失败，即使 HTTP 状态为 2xx，工具步骤也会失败，不会等待后续回执门禁才发现。`408`、`425`、`429` 和 `5xx` 会作为瞬时失败进入工作流重试；其他 `4xx`、无效 UTF-8、无效 JSON、数组回执、业务失败、数据值超限及契约不匹配均视为永久失败。界面与日志只显示归一化错误，不回显外部响应正文或服务端凭据。
