# 跨运行业务操作防重

真实工具节点可显式配置 `toolOperation`。同工作区、同工具、同动作、同业务范围及同标识的请求，即使来自不同运行、助手或版本，也共用持久操作记录。成功后复用回执，不再调用业务系统；完整请求改变时明确失败，不拿旧回执冒充新金额或新业务结果。

## 没有显式业务键的 HTTP 写步骤

当前后端适配沿用独立 HTTP 候选的规则：只有服务端明确登记 `operationKind: "action"`、`businessIdempotency: true` 和真实有效期时，HTTP 步骤才自动使用持久账本。不根据 POST、名称或模型草稿猜测写入性质。HTTP 省略协议仍按原 `http-json` 处理，明确只读及未启用保护的旧 HTTP 路径保持兼容；已经有该步骤保护记录时，撤回保证、有效期或性质不能让重试降为直接调用。记录归属或数据库状态未知时停止，不把错误当作没有记录。

默认记录只保护同一运行的同一次 SDK 步骤调用；不同运行或循环的新调用有不同定位，不能把它声称为跨运行业务防重。跨运行复用仍须配置下面的显式业务键。默认 HTTP 的 `http-default-step:v1` 持久定位沿用原独立候选，ASCII 外部键保持历史值，中文内联名称采用现有安全头编码，不截断或改写持久名称。

完整 `action/input/outputs` 信封进入请求摘要与实际发送，容量仍为 512KB；零金额和否定值不丢失。期限锚定 SDK 的首次步骤时间，并与已有记录的更早截止取最小值；租约接管、重试或人工操作不能续期。没有历史记录的旧重试只能进入待核对，不能把它当新首次写入。成功回执按原冻结、当前字段和脱敏规则复用，不重新发送；未知、过期或非法回执不能伪装成成功。

本次只适配 HTTP 默认分支，现有 MCP 默认步骤的命名空间、请求摘要、外部键及显式跨运行业务键算法保持不变，不修改迁移、表结构、SDK 或公开前后端契约。HTTP 明确登记的性质必须与冻结一致；旧版本不一致时须重新发布，不能让草稿中的 `read` 覆盖登记的 `action`。编译器对旧目录的推断标记仅存在于模块内部，不作为公开参数或持久字段。

新增普通回归使用内存持久层或传输替身；`tests/workflow/http-default-tool-operation.test.ts` 另保留两项真实 SDK 步骤、隔离数据库和本机假服务场景。后者只验证工具步骤和重试，不是创建、发布、审批或完整助手验收。必须先取得安全隔离库证明并通过原显式标记门槛，不能仅设置标记就运行；当前均尚未执行，不因源码存在宣称通过，也不改变原验收用例或计数门槛。

## 外部工具的必要约定

服务端注册表必须声明 `businessIdempotency: true` 和 `businessIdempotencyRetentionMs`，后者填写业务系统真实保证的最短键有效期，范围为 5 分钟至 365 天。未声明或不支持时不能启用该节点配置。代码无法替外部系统证明其声明，需要接入验收确认。

业务系统必须按 `Idempotency-Key` 原子处理并发请求；重复键返回同一结果，不产生第二次副作用。发生已写入但响应丢失时，只有这一外部保证才能安全重试。不得给忽略该请求头的系统虚报支持。

本系统在发请求前保存防重记录，只保存业务标识和完整请求的 SHA-256，不保存标识原文、输入正文或工具凭据。请求指纹包含完整 HTTP 信封、地址、方法、规范化请求头和声明的键有效期；重新绑定地址、切换账号、轮换凭据或改动有效期不会悄悄复用旧请求。即使凭据轮换对应同一账号，也先拦截冲突，不猜测外部身份是否一致。

每条操作保存不可延长的重试截止时间，较声明的有效期提前两分钟预留余量；过期的未确认操作进入待核对，不自动再发请求。已成功操作的回执没有自动过期，不会因外部键过期而重放。

## 配置

```json
{
  "toolOperation": {
    "scope": "order-create",
    "key": { "kind": "input", "path": ["orderId"] }
  }
}
```

`scope` 是明确的业务动作范围，只允许字母、数字、点、下划线和短横线，最多 100 字符。`key` 共用字段映射来源：任务输入、步骤结果或固定值。标识必须是非空短文字（最多 256 字符）或安全整数，数字和文字不混用。不会猜测缺失标识，也不将对象转成文字。

循环中应选择当前项的业务标识，例如来源 `{"kind":"output","nodeId":"items","path":["currentItem","orderId"]}`。引用内联结果时使用完整步骤标识。保存、导入、发布、恢复和启动前检查来源是否存在。

建议同时使用 `inputMapping`，只传业务工具真正需要的字段。未选择的任务备注改变不会影响请求指纹；实际发送的金额、上游结果或其他字段改变则发生冲突。仅当业务确实要求再次执行时，才使用新的业务操作标识；不要为绕过冲突随意换范围。

## 并发与回执

唯一索引和短事务完成原子领取；外部请求不在数据库事务内执行。活跃租约最长两分钟，其他运行返回可重试等待；过期租约仅在防重有效期内接管，并复用原外部键。回执持久化失败也不会换用新键。

成功回执必须通过冻结和当前工具输出契约，并满足可保存 JSON 约束。缓存前脱敏，脱敏后再次校验；坏回执、业务失败和永久 HTTP 拒绝进入待核对，不因手动重跑再发写入。取缓存时重新按本次冻结和当前契约检查，不跳过新版本字段规则。

## 人工核对后继续

后端提供 `getToolOperation(workspaceId, operationId)` 和 `resolveToolOperationAction`，结构在 `src/contracts/tool-operation.ts`。查询不跨工作区，不返回防重标识原文或工具秘密。目前没有专用前端操作台，不虚标可视化入口。

HTTP 入口为 `/api/tool-operations/<业务操作标识>`：

- `GET` 返回 `{ "ok": true, "operation": ... }`，仅查询当前演示工作区；缺失记录返回 404。
- `POST` 通过服务端写入口提交下面的核对对象。地址与正文标识必须一致，且须有与本站一致的 `Origin` 请求头；无来源或跨站请求返回 403。命令行调用也要明确设置本站来源，这不是身份认证，接口仅供受保护的测试或内网部署使用。
- 正文最多 1MB 加 4KB，回执本身最多 1MB；非法结构或编码返回 400，超限返回 413，业务冲突返回 409。
- 暂时无法确认写入结果返回 503、`Retry-After: 2` 和 `retryable: true`，必须保留相同 `requestId`、标识及正文重试；成功返回 `{ "ok": true }`。所有响应禁止缓存。

定位待核对操作可先请求 `GET /api/tool-operations?status=blocked&limit=20`。可筛选 `pending`、`completed`、`blocked`，省略状态则查询全部；`sourceRunId` 仅表示首次创建操作记录的运行，并不包含所有复用过该操作的运行。页大小为 1 至 50，默认 20。列表仅返回摘要和核对次数，不批量返回业务回执、核对正文或请求指纹；详情通过上述单条接口读取。

列表按创建时间和记录标识倒序，返回 `nextCursor: { createdAt, id }` 或 `null`。下一页把时间原样放入 `before`，标识放入 `beforeId`；二者必须同时提供。游标时间保留数据库微秒，不能先转成 JavaScript Date 再格式化，否则可能漏掉密集记录。新增首页记录不会重复出现在旧游标的下一页；状态变化后的列表可刷新重查。未知参数、重复参数、非法筛选或不完整游标返回 400，跨站读取返回 403，所有响应禁止缓存。

```json
{
  "operationId": "实际业务操作的 UUID",
  "requestId": "本次核对专用的 UUID",
  "reason": "已在业务系统查到完成结果",
  "kind": "record-receipt",
  "confirmedCompleted": true,
  "receipt": { "receiptId": "实际业务回执" }
}
```

人工核对必须提供独立请求标识、原因和明确确认：

- `kind: "retry"`，`confirmedNotExecuted: true`：已查业务系统并确认未执行后，才重新开放同键尝试；不能延长截止时间，超期时拒绝。
- `kind: "record-receipt"`，`confirmedCompleted: true`：已在业务系统查到完成结果后，记录满足当前输出契约的实际回执；此操作不调用外部系统。后续复用轨迹明确标记人工核对，不声称系统自动验证了外部状态。

核对与追加记录在同一事务完成，保存操作者、时间、原因及请求指纹，最多 50 条；相同请求可安全重试，不可换内容。正在执行的操作和已完成操作不能改写。不提供删除防重记录或清空历史的入口。

## 上线与验收

追加迁移 `0024_narrow_thunderbird.sql`、`0025_gifted_mikhail_rasputin.sql` 和 `0026_lying_veda.sql`；第二项为旧记录默认关闭重试窗口，不猜测历史有效期，第三项补齐摘要列表与状态筛选的稳定翻页索引。上线前先在隔离数据库迁移并验收，再由负责人确认生产迁移。健康检查包含操作表、唯一索引、列表索引、必填工作区及截止字段；构建不会自动迁移生产库。

新增受控 HTTP 服务与真实持久 Workflow 测试覆盖手动重跑、金额冲突以及写入已完成但响应丢失后的同键重试；数据库测试覆盖并发、跨工作区、账号变更、租约接管、超期阻断、坏回执、HTTP 人工核对、摘要隔离及微秒游标稳定翻页。这些新增集成测试待独立 Neon CI 验收，不能把测试代码存在当作通过。外部真实工具的保证、实际业务副作用和账号配置仍需独立验收。
