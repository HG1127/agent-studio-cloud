# 默认成果流：实现中的后端能力

本分支先加入共享成果帧和纯补送判定，不调用 SDK、数据库、模型或业务工具。尚未接入运行、持久发送记录、真实读回、关闭或取消对账；不能据本模块或模拟测试宣称默认成果流已经接通。

成果帧统一由 `src/contracts/default-result-stream.ts` 定义。仅已有完成状态、真实完成时间和合法两兆字节成果能冻结；不填当前时间，不截断正文，不把零、否定值或未获确认结果改成成功。帧标识沿用任务标识，正文哈希使用固定字符排序而非宿主语言排序；发送端必须原子保存该帧与实际根任务、工作区、引擎运行及启动归属。凭据未隐藏时拒绝发送，不为补送修改已冻结业务正文。

读回必须确认同一归属、同一帧和同一正文。同一帧的物理重复允许逻辑去重，不承诺物理恰好一次。核对状态未知、读回未覆盖当前尾部或前次生产尚未停止时不能并发补写或关闭；已有正确帧仅关闭并再核对。关闭后的缺帧、冲突或不完整成果不能靠重新写入修复。`verified_snapshot` 与 `producerSettled` 是待实现可信适配器提供的证据，不是客户端输入或 SDK 步骤返回的别名。

冻结期望帧和读回帧均先验证无执行行为、共享结构和哈希；不能只信保存过的哈希。核对最多六十四个完整应用帧，存储尾部已超出该预算时明确失败，不能永远返回无法满足的重新核对要求。结果自身的三十二层、五万内容项上限与帧包装分开计算。

已安装 Workflow/core 4.8.9 的 `getWritable()` 及关闭承诺仍需独立持久确认。SDK 步骤会缓存返回值而流刷新在后台，读回又可能在元数据请求异常时信任 EOF；仅重新调用已缓存步骤或确认 EOF 不够。常规写入和关闭应使用公开默认写流；精确 `done`/尾部核对须先证明与该版本、实际运行和提供器相容，不能从流清单猜默认身份。本地提供器流清单登记没有并发锁，关闭后的补写也不保证可读。

接线验收必须覆盖：业务成果与发送意图原子保存、启动绑定丢失、跨运行及子流程、人工拒绝、取消与完成竞争、后台追加失败、关闭与数据库确认 ACK 丢失、半帧和重复帧、有界重试与读回取消。发送失败不能改写已完成成果，恢复不能重新调用模型、审批或业务工具。真实数据库和 Workflow 验证只交隔离本地 CI；需要的外部账号、密钥、预览部署仍记录后等待人工配置。
