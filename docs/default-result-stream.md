# 默认成果流：后端接线与验收边界

本分支已提供默认成果流的候选实现：冻结成果帧、持久投递表定义、业务完成与发送意图的同一事务、公开 SDK 适配、根流程等待及后端核对入口。依赖锁文件已固定 SDK5，但真实数据库迁移应用、实际 SDK 持久流与完整链路验收尚未完成，不能宣称成果流、MVP 或生产部署已验证可用。未修改页面、视觉组件或全局样式。

成果帧由 `src/contracts/default-result-stream.ts` 定义，投递持久记录、操作输入和前端视图统一在 `src/contracts/default-result-delivery.ts`。仅已有完成状态、真实完成时间和合法两兆字节成果能冻结；不截断正文，不把零、否定值或未获确认改成成功。正文哈希采用固定字符排序；只发送服务器保存的同一帧，不为补送修改已冻结正文。未隐藏凭据明确拒绝。

业务完成先锁运行行，仅新 SDK5 标记且原始父标识为空、来源为手动/定时/验收的根任务原子冻结同一正文、真实完成时间、工作区及实际 SDK 归属；当前执行身份不匹配时拒绝。子任务、协作遗留缺父标识及历史 SDK4 任务不冒充默认根投递。完成重入核对原保存成果，不重建正文、时间或哈希；取消/失败竞争返回明确停止，不继续投递。

`package.json` 与 `pnpm-lock.yaml` 均精确选择 `workflow=5.0.0` 与 `@workflow/vitest=5.0.0`。SDK5 公开 `Run.getWritable({ ops })` 在每次操作后释放 writer 并等待自己的全部持久操作；日志使用 trace 命名空间和独立 ops，不关闭共享日志流，不把日志刷新错误留到模型或工具步骤的私有操作数组。

依据 SDK5 固定版本源码派生默认流名称，用公开 Run 尾部和 World 前后元数据交叉核对，最多读取六十四个完整应用帧。同帧物理重复允许逻辑去重，不承诺物理恰好一次。读满有界快照后释放锁、等待独立读取操作，再取消开放流，EOF 不是存储成功证据。整个适配调用共用总时限，写入不重置时限。关闭后的缺帧、冲突或不完整成果不能靠补写修复。版本相容性仍待真实 SDK 验收。

发送前保存独占操作凭据，不能按租约超时或 SDK 取消回收发送中记录。旁路观察失败只能为正在发送的记录保存安全原因，必须保留发送状态及原凭据，使原发送者仍能登记自己的回执。未知 ACK 或 wire 前后进程退出时保留待核对，不自动补写、关闭或重跑模型/工具；明确 own ops ACK 后读回失败才允许只读核对及必要关闭。缺少前次 sender 已停止的公开证据时仍需人工核对，当前没有客户端强制解锁入口。投递失败不改写已完成业务成果。

根 Workflow 只在成果流可信读回且明确关闭后结束。已识别的 SDK 观察失败持久保存待核对原因，发送前明确无 ACK 时保存释放领取结果；两者返回安全非终态而不是靠有限步骤重试消耗原根生命周期，仍不放行无法可信核对的流。未确认时使用 createHook 等外部消息，不自建轮询；每轮随机 token 与等待步骤身份同存，步骤重试复用该 token，防止迟到恢复请求串入新等待。先注册再读一次终态覆盖早到恢复。恢复动作只用服务器保存的归属和当前 token，客户不能提交 producer 状态、SDK 标识、正文或哈希。数据库归属或持久状态不可读取/保存仍抛安全错误，不把结构损坏和未知生产者当作可自动恢复。

接口：`GET /api/runs/{任务标识}/default-result` 读取有限投递视图；同一路径 `POST` 接受严格的 `{ "mode": "verify" | "retry" }`，只核对或恢复成果投递。写操作统一经 Server Action，工作区沿用后置登录阶段的演示上下文；不是正式登录权限系统，未新增前端页面。默认 SDK 成果流与既有外部网页接收方投递账本是两种能力，不能互相冒充送达。

## 成果终态后的恢复通知

成果投递已为 `confirmed` 或 `failed` 不代表等待恢复消息的根流程已经结束。存在服务器保存的等待入口时，视图继续允许 `canVerify: true`，但保持 `canRetry: false`；客户端可沿用原地址与 `{ "mode": "verify" }` 核对及重试控制消息，不能重新创建业务任务或重发成果。

恢复消息未获确认，且公开执行状态尚未证明根流程已完成、失败或取消时，成功回执额外带 `workflowNotificationPending: true`、`workflowNotified: false`。HTTP 返回 `202`、`Retry-After: 2` 和 `Cache-Control: no-store`；`delivery` 保留真实的投递终态。这不是投递失败、业务回滚或通知已经送达。通知失败后的状态读取最多等待两秒，读取失败、超时或归属不符都保留待核对，不据此推断根已经结束。

控制消息已获确认，或消息响应丢失但公开引擎已明确结束时，恢复接口仍返回原 `200` 成功结构，不添加待通知标记。没有保存等待入口的历史终态不会虚构待通知。标记只由服务器产生；请求契约、等待令牌与执行身份不向客户端开放。早到消息仍由根注册入口后的一次终态读取覆盖；已注册入口的通知失败则有明确的可重试回执。没有新增后台轮询或自动恢复任务。

官方 SDK 流生命周期文档提示执行结束时会关闭流；不同提供器实现仍须分别验证，本候选拒绝向已完成 SDK 根追加。Local 官方实现把不存在流定义为空、未关闭、尾部 -1；Vercel 客户端首次元数据查询失败不归一为空流。真实 Vercel 首次缺流是否返回有效空元数据仍无验收证据，404 明确拒绝写入，不伪造成功。

验收源码包括纯判定、完成、SDK/数据库替身、Hook、日志回归，隔离数据库事务竞争回归和真实 SDK 故障夹具。最近已验证基底 `328bc71` 的52个完整普通测试文件共1135例及完整类型检查、全仓 lint，其中默认成果帧纯函数35例通过；这不是 SDK 适配、持久发送、数据库或真实 Workflow 验收通过。本批新增通知恢复代码与回归尚未执行，不沿用旧基底结论。

最终仍须在同一候选完成类型、lint、完整 Vitest、build、隔离空 ci_test 全数据库、全部实际 Workflow、原41项数量守卫、E2E、临时资源清理及受保护预览访问。历史迁移不修改，不用普通替身测试代替隔离验收。外部账号、密钥、专用项目归属、生产迁移和真实业务接收方配置记录后等待人工处理。
