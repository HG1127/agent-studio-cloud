# 等待消息 HTTP 接入契约

发布版本中的“等待外部消息”节点会暂停运行，直到业务系统提交一条符合节点字段契约的消息，或等待超时。每次等待都会生成独立的一次性提交凭据。

## 获取接入信息

打开对应运行详情，在“提交继续消息”区域展开“让外部系统继续这次运行”，分别复制：

- 接入地址：本次等待的完整 HTTPS 地址。
- 提交凭据：只对本次等待有效的秘密值。

不要把提交凭据写入日志、URL、仓库或前端公开配置。运行继续、超时或取消后，这组接入信息即失效。

升级前已经进入等待、但尚未生成独立提交凭据的旧运行，不会展示执行引擎内部令牌，也不接受外部系统调用；请直接在运行详情页面提交消息。

## 请求格式

向复制的接入地址发送 `POST` 请求：

```http
Content-Type: application/json
X-Wait-Event-Token: <复制的提交凭据>
```

请求体必须是 JSON 对象，并满足该等待节点配置的字段契约。例如：

该入口面向服务端业务系统。浏览器页面只能从 Agent Studio 同站提交；跨站浏览器请求会被拒绝，避免旧任务的接入地址被其他网站滥用。

```json
{
  "complete": true,
  "customerId": "customer-123"
}
```

示例请求：

```bash
curl --request POST '<复制的接入地址>' \
  --header 'Content-Type: application/json' \
  --header 'X-Wait-Event-Token: <复制的提交凭据>' \
  --data '{"complete":true,"customerId":"customer-123"}'
```

## 响应与重试

- `200`：消息已接收，运行会继续。
- `400`：请求体不是合法 JSON 对象，或不满足节点字段契约。
- `403`：提交凭据缺失或不匹配，或请求来自其他浏览器站点。
- `404`：运行不存在。
- `409`：运行已经不在等待这条消息、该次等待已超时且消息未被接收，或同一提交凭据被改用于不同消息。此类响应不能当作原消息成功。
- `500`：暂时无法读取或保存消息回执；保持请求内容不变后重试。
- `503`：相同消息正在处理，或执行引擎是否已经接收仍在确认。即使运行已前进，只要该次等待的结果轨迹尚未落库，也不会仅凭运行状态返回成功。按响应的 `Retry-After` 秒数等待后，使用完全相同的地址、凭据和 JSON 内容重试。

服务端会为一次性凭据保存幂等回执：相同凭据、相同 JSON 数据重复提交时只恢复一次工作流，成功后重复提交仍返回 `200`。对象字段顺序不同不影响判定，但字段值和数组顺序必须保持一致。网络超时、`500` 或 `503` 后可以安全重试；`400`、`403`、`404`、`409` 需要修正请求或停止发送。不要为一次等待重新拼接接入地址，也不要复用其他运行的提交凭据。
