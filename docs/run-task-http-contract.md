# 程序化任务 HTTP 约定

此入口把已有的操作员启动能力提供给程序调用，复用页面的冻结版本、输入校验、启动租约和请求防重。不是公网 Webhook，也没有新增身份认证；仅用于已有访问保护或受控内网部署。可选终态成果投递另按服务端接收方与防重约定启用。`Origin` 是防跨站写入检查，不是调用方身份凭据。不要为接入关闭部署访问保护。

任务共享结构定义在 `src/contracts/run-task.ts`，审批共享结构定义在 `src/contracts/run-approval.ts`，类型由 Zod 推导。接口不接受工作区、调用来源、执行快照或回调地址；来源仍记为手动启动。基础任务与审批能力无需新增环境变量或数据库迁移。可选 `delivery: { "targetId": "服务端接收方别名" }` 启用终态成果可靠投递，要求追加迁移和接收方配置；原请求不得添加、删除或更换投递选择，完整约定见 `docs/run-delivery-http-contract.md`。

## 提交任务

`POST /api/runs`，必须带与请求地址一致的 `Origin` 和 `Content-Type: application/json`。带 `Sec-Fetch-Site: cross-site` 的请求也会拒绝。服务端调用须遵循同样要求，并另外满足现有部署访问保护。

```json
{
  "agentId": "00000000-0000-4000-8000-000000000001",
  "versionId": "00000000-0000-4000-8000-000000000002",
  "requestId": "00000000-0000-4000-8000-000000000003",
  "input": { "amount": 0, "approved": false }
}
```

示例标识须替换为实际助手与版本，输入须符合该版本的字段契约。`requestId` 必填，调用方应在第一次发送前生成并持久保存；`versionId` 可省略。输入最大 100KB，总请求体最大 104KB，沿用已有 JSON 层级、项数和保留字段限制；读取请求体按实际 UTF-8 字节计数，不只相信声明长度。

- 首次不指定版本：选择当时最新的已上线版本，并冻结本次运行。
- 指定版本：仅接受此助手在当前工作区的已上线或已退役冻结版本；草稿和待验收版本不能通过此入口运行。
- 同一请求标识与同一助手、等价输入再次提交：返回原运行，不再次启动工作流；与页面启动共享 `manual:<requestId>` 防重空间。
- 标识按 UUID 小写表示归一化；同一个标识仅改变字母大小写不会生成第二个任务或误判版本冲突。
- 原请求省略版本重试：仍返回原冻结运行，不随之后的发布漂移。
- 原请求显式指定另一版本或改变输入、助手：返回冲突，不复用错误任务。
- 要发起真正的新任务，使用新的请求标识。任务启动防重不等于业务写入防重，外部工具仍须按其防重约定接入。

接收成功返回 `202`，`Location` 为状态入口：

```json
{
  "ok": true,
  "runId": "00000000-0000-4000-8000-000000000004",
  "links": {
    "status": "/api/runs/00000000-0000-4000-8000-000000000004",
    "result": "/api/runs/00000000-0000-4000-8000-000000000004/result",
    "report": "/api/runs/00000000-0000-4000-8000-000000000004/export",
    "events": "/api/runs/00000000-0000-4000-8000-000000000004/events",
    "view": "/runs/00000000-0000-4000-8000-000000000004",
    "approvals": "/api/runs/00000000-0000-4000-8000-000000000004/approvals"
  }
}
```

`202` 只代表任务已接收，可能仍在排队、执行或等待人工处理，不代表业务完成。确定性业务拒绝返回 `409`；参数、编码或 JSON 错误返回 `400`，体积超限 `413`，内容格式错误 `415`，跨站写入 `403`。

新根达到工作区执行链名额返回 `429`、`retryable: true`、`resourceLimit` 与 `Retry-After: 2`；不建立运行或投递意图、不启动引擎，已接收原请求仍找回原任务。设置、冻结上限和准确口径见 [资源准入约定](./execution-resources-http-contract.md)。

启动结果暂时不确定时返回 `503` 与 `{ "ok": false, "error": "…", "retryable": true }`，同时给出 `Retry-After: 2`。保留同一请求标识、助手、版本参数和输入重试，不能因为响应丢失就生成新请求。缓存刷新失败不会把已接收任务伪报失败。

已接收任务可能仍在排队。若长时间停留在 `queued`，可用原请求再次提交：启动租约到期后由既有恢复逻辑补启原运行，仍复用原版本与运行标识。状态读取不会偷偷启动工作流；不要为补启创建新请求标识。

## 状态与最终结果

`GET /api/runs/<runId>` 返回 `{ "ok": true, "task": { ... } }`。状态包含助手名称、冻结版本、开始结束时间、脱敏错误、入口链接和 `terminal`。只选择必要元数据，不加载或返回运行输入、上下文、过程输出、完整版本快照或工作流内部句柄。

`GET /api/runs/<runId>/result` 返回同样的 `ok/task` 包装，任务字段为 `runId`、`status`、`ready`、`result`、`error`、原冻结版本的 `outputContract` 和入口链接。

| 任务状态 | `terminal` / `ready` | 结果接口状态码 | `result` |
|---|---|---|---|
| `queued`、`running`、`waiting_approval`、`waiting_event` | `false` | `202`，带 `Retry-After: 2` | `null` |
| `completed` | `true` | `200` | 实际最终业务 JSON，最大 2MB |
| `failed`、`cancelled` | `true` | `200` | `null`，同时提供脱敏原因 |

`ok: true` 表示读取成功，`ready: true` 表示任务已终结；只有 `status: completed` 才表示执行成功。失败或取消的过程成果绝不作为最终交付返回。零金额、`false`、对象、数组等保持原有 JSON 类型，契约允许的最多 32 层业务字段完整保留，凭据在有界 JSON 校验后按对象结构隐藏；无效或超限数据明确拒绝，不通过截断字段伪报完整交付。

两个读接口均不接受其他工作区选择；不存在或不可访问统一返回 `404`。非法运行标识 `400`，提供跨站来源 `403`；临时读取或存储记录不符合契约返回 `503` 与可重试标记，不回显连接串或原始存储错误。所有接口都带 `Cache-Control: no-store`。

可用 `links.events` 接收现有 SSE 状态与轨迹，`links.view` 打开人工审批或等待消息入口，`links.report` 下载运行报告。生产编排仍使用 SDK Hook 暂停和恢复，没有新增工作流内轮询。

## 尚未包含的能力

独立的外部任务来源、面向业务集成的限定范围接入凭据与签名 Webhook 仍待后续实现。终态成果投递已有独立后端协议与持久记录，但须接收方配置、调度及本提交隔离验收，不能把本机测试服务替代真实模型和业务系统联合验收。

## 取消任务

`POST /api/runs/<runId>/cancel` 沿用相同部署访问保护、同源和 JSON 内容要求，总正文最大 4KB，必须明确提交：

```json
{ "confirmed": true, "scope": "execution-chain" }
```

取消作用于整条执行链，不是只停止当前画布节点：从协作子运行请求取消可能同时停止仍活跃的上级、兄弟与后代运行。调用方须在确认前展示或核对这一范围，不能把范围改成 `single-run` 或省略确认。接口不接受请求正文中的运行标识、工作区或其他字段。

成功返回 `200` 与 `{ "ok": true, "runId": "…", "scope": "execution-chain", "links": { ... } }`，表示取消终态已保存，后续步骤受终态守卫阻止；不撤销已完成的业务副作用，也不把部分成果当成最终交付。未处理的审批关闭，历史已处理决定保留。已取消任务可按原任务安全重试，以补偿执行引擎停止或验收汇总；已完成或失败任务不再改写为取消，返回 `409`。

启动尚未确认或临时存储故障返回 `503`、`retryable: true` 和 `Retry-After: 2`，调用方沿用原任务重试。无法确认结果时不能换任务标识。其他参数、来源、格式与大小错误沿用 `400`、`403`、`415`、`413`。所有响应禁止缓存。

## 程序化审批

沿用受保护部署的操作员范围，不是开放外部审批 Webhook，也不新增身份凭据。仅处理当前工作区和路径指定任务的确认；不返回 Hook token、引擎句柄、整份运行输入或上下文。新任务回执的 `links.approvals` 提供本次确认列表入口；旧回执可以不带此字段，存在时必须属于同一任务。

`GET /api/runs/<runId>/approvals` 返回有界摘要，默认 20 条、最多 50 条，按创建时间和记录标识倒序。可用 `status=pending|approved|rejected` 筛选；未知或重复参数拒绝。响应 `nextCursor` 的 `createdAt` 与 `id` 要原样传入下一页的 `before` 与 `beforeId`，不能经 Date 转换丢失微秒。摘要不包含审批正文或备注；过长标题带 `titleTruncated: true`，完整内容须读取单条。

`GET /api/runs/<runId>/approvals/<approvalId>` 返回 `ok/approval`，含原审批决定、备注、业务理由及完整成果快照。结构化成果保留零值、否定值和有界深层字段，凭据在对象序列化前隐藏；正文最大 2MB。坏快照返回 `409`，不以空成果冒充可审核内容；旧版没有模型成果的确认允许 `review: null`。不存在或不可访问返回 `404`，临时读取失败 `503`；跨站读取 `403`。

列表与详情提供当前任务状态、`decisionConsumed` 及 `state`：`pending` 表示等待决定，`resume-needed` 表示决定已保存但仍待恢复，`processed` 表示无需恢复这项确认，`unavailable` 表示不能处理。`processed` 不代表业务任务执行成功；最终任务状态仍通过状态和结果接口读取。

`POST /api/runs/<runId>/approvals/<approvalId>` 必须同源、使用 JSON，总正文最大 4KB，提交：

```json
{ "confirmed": true, "decision": "approved", "note": "已核对实际金额" }
```

`decision` 为 `approved` 或 `rejected`，可选备注最多 500 字符；不接受正文中的路径标识、工作区、`resumeOnly` 或其他字段。成功 `200` 与 `recorded: true` 只代表该决定已保存或找回，不代表任务完成。审批记录标识本身就是本次决定的防重依据，重试须保留同一任务、确认记录、决定和备注；备注按去首尾空白和凭据隐藏后的内容比较。不同决定、修改或省略已保存的非空备注返回 `409`，绝不改写历史决定。

事务或恢复响应丢失时核对同一记录；决定已保存但恢复尚未确认返回 `503`、`saved: true`、`retryable: true` 和 `Retry-After: 2`，沿用原请求重试。原确认已被实际工作流消费，即使现在等待下一项确认，也直接找回原决定，不再次恢复旧 Hook、不跳过新的确认。取消后的未消费决定不恢复；已消费的历史决定仍能查回。审批恢复使用既有 SDK Hook，没有新增工作流轮询或自动新建任务。

旧页面动作仍保持原有显式继续语义。接口之外的真实业务账号、外部接入和生产环境验收仍按人工配置清单执行，不能为调用接口关闭访问保护。所有响应禁止缓存。
